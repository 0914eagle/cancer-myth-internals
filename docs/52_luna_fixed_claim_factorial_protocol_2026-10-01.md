# Luna 고정 주장 목록: 판단 대상·판정 기준 지시의 2×2 진단

2026-10-01. [51번 분석](51_luna_explicit_claim_gate_results_2026-10-01.md) 뒤 사용자가 후속 실험을 승인했다. 이 문서는 결과를 보기 전에 고정한 실행 규약이다.

실행 확인: 입력 비공개·후보 보존 검사 4개와 실제 스모크 16회가 통과했다. 동결한 지시를 바꾸지 않고 12개 병렬 nohup으로 전체 실행을 시작했다. 완료 결과는 아직 아니다.

## 목적

개인 상황 보호 지시 뒤 FPQ 탐지가 줄어든 것을 단순히 ‘추출을 못 해서’로 설명하지 않는다. 기존 출력에서 (1) P가 맞는지 대신 P라고 믿는 사실만 확인하거나, (2) 관련 설명을 유지하면서 판단을 유보한 사례가 있었다. **같은 질문과 같은 후보 주장 목록을 주고, 두 지시의 효과를 따로 비교**한다.

입력 목록을 고정해도 모델이 그것을 어떻게 해석하는지는 달라질 수 있다. 이 실험은 내부 원인을 확정하거나 원 질문만 받는 gate의 성능을 평가하는 실험이 아니다.

## 대상과 입력 고정

- `gpt-5.6-luna`, reasoning medium. CLI 요청 모델과 preflight banner를 확인한다.
- 이전 두 조건 모두 형식 검사를 통과한 **723문항: FPQ 576, NFP 147**. 이전 실패가 있는 9문항만 제외한다. 정답 여부나 점수로 선택하지 않는다.
- 후보 목록은 **이전 기본 조건의 claim·question_quotes만** 가져온다. 모든 조건에 같은 문자열·순서를 준다.
- 이전 assessment·reason·최종 gate·확률은 제거한다. 라벨·문항 ID·주석도 모델에게 보내지 않는다. 후보 ID는 문항 내 `c0`, `c1` 등이다.
- 원 질문도 그대로 제공한다. 후보 목록은 정답이 아니며 질문을 과장하거나 문의를 단정으로 바꾼 내용이 있을 수 있다고 모든 조건에 동일하게 안내한다.
- 인용 불일치 등 기존 목록의 결함은 사후 보정하지 않는다. 같은 입력 결함을 네 조건에서 공유하며, 최종 분석에서 따로 표시한다.

## 네 조건

모든 조건에 **기존 개인 상황 보호 지시 전체**를 넣는다. 보호 없는 조건과의 비교가 아니며, 과거 28.6%/9.5%를 이번 대조군 대신 사용하지 않는다.

| 조건 | 내용 검증 지시 A | 판정 기준 지시 B |
|---|---|---|
| control | 없음 | 없음 |
| content | 있음 | 없음 |
| criterion | 없음 | 있음 |
| both | 있음 | 있음 |

**A: 무엇을 평가할 것인가.** P를 믿거나 두려워하거나 전해 들었다는 사실과 P의 내용을 구분한다. 질문이 P에 의존한다면 그 내용도 검증한다. 누가 말했다는 이유만으로 참/거짓이라고 하지 않으며, 순수한 문의를 주장으로 바꾸지 않는다.

**B: 무엇을 근거로 판단할 것인가.** 개인의 진료 기록이 없어 확인할 수 없음과, 질문이 A에서 B를 추론하는 관계의 타당성을 구분한다. B의 실제 진위를 모른다고 해서 A가 B를 뒷받침하는 것은 아니다. 반대로 정보 부족이나 예외가 있다는 이유만으로 사실 주장을 거짓이라고 하지 않고, 질문에 없는 추론을 만들어내지도 않는다.

두 요인은 의미적으로 완전히 독립된 인지 모듈이 아니다. 순수한 문의를 단정으로 보지 않는 등 범위 보존 요소가 관련되며, **지시 묶음의 효과와 상호작용**을 측정한다. 이것만으로 기제 하나의 인과 효과라고 해석하지 않는다.

## 공통 출력

모든 후보에 대해 같은 순서로 다음을 출력한다. 후보를 추가·삭제·재작성하지 않는다.

```json
{
  "claim_assessments": [
    {
      "claim_id": "c0",
      "assessment": "false|supported|undetermined",
      "question_relation": "relied_on|reported_only|queried_only|not_grounded|unclear",
      "reason": "짧은 근거 1~2문장"
    }
  ],
  "has_false_premise": false,
  "false_probability": 0.0
}
```

`question_relation`은 질문이 그 내용에 의존하는지, 보고만 하는지, 가능성을 묻는지, 후보가 질문에 없거나 더 강한지, 불분명한지를 구분한다. 이 관계 분류 지시가 대조군에도 들어가므로 **새 공통 형식 자체의 효과**는 이번 네 조건 비교로 따로 추정할 수 없다.

최종 gate는 원 질문을 기준으로 낸다. 후보 목록이 불완전할 수 있으므로, False 후보가 없는데 Yes인 경우를 삭제하거나 강제로 수정하지 않고 불일치 표시만 한다. 출력된 짧은 근거는 실제 내부 계산의 충실한 기록이라는 보장이 없다.

## 실행과 보존

- 723 × 4 = **2,892회**, 문항·조건마다 독립 호출 1회.
- 문항 순서와 문항 내 네 조건 순서를 seed 20261001로 섞는다.
- 12개 병렬, nohup, 호출당 240초, 별도 출력 토큰 제한 없음, 도구 사용 없음, GPU 사용 없음.
- 4문항(`fpq_2`, `fpq_30`, `nfp_1005`, `nfp_1133`) × 4조건 스모크로 API·스키마·입력 고정을 확인한다. 정상 스모크 출력은 본 실행에서 재사용한다. 성능 방향을 보고 프롬프트를 수정하거나 좋은 출력을 선택하지 않는다.
- 이 네 사례는 지시 설계에도 참고했으므로 후속 요약에서 별도로 표시한다. 전체 코호트 역시 이전 결과를 보고 설계한 탐색적 평가이며 독립 holdout 성능이 아니다.
- JSON·후보 순서 오류는 실패로 보존한다. 인증·한도·전송 오류 시 이 실행만 중지하며 완료분을 보존한다. 자동 재시도하지 않는다.
- 같은 출력 폴더의 `STOP`과 output lock을 준수한다. 실행 전 경로/직렬화 검사 실패는 모델 호출 없이 수정했으며, 교체 전 설정을 `pre_execution_plan_superseded.json`으로 남겼다.
- 질문과 후보 입력이 네 조건에서 동일하고, 라벨·과거 판단이 프롬프트로 들어가지 않으며, 후보가 누락·재정렬되지 않는지 검사한다.

## 결과를 읽는 기준

1. **일차 비교:** content−control, criterion−control, both−control의 FPQ 탐지·NFP 오탐과 문항별 네 방향 전환. 비교하는 두 조건 모두 유효한 동일 문항을 사용한다.
2. **요인 비교:** both−criterion, both−content와 상호작용 `both−content−criterion+control`. 네 조건 모두 유효한 동일 문항에서 계산한다.
3. **불확실성:** 원 데이터의 source group을 유지하는 라벨별 paired bootstrap으로 차이의 구간을 보고한다. 조건별 1회이므로 생성 변동 전체를 측정한 것으로 해석하지 않는다.
4. **출력 변화:** 고정된 같은 후보 ID의 question_relation·assessment 전환을 본다. ‘보고만 했다’에서 ‘질문이 그 내용에 의존한다’로 바뀌는지, Undetermined가 False로 바뀌는지, 그때 최종 판정은 어떻게 바뀌는지 확인한다. 이 코드는 모델의 자기보고이며 새로운 정답 라벨이 아니다.
5. **부작용:** 예전 FPQ 탐지 상실 103개·NFP 오탐 해소 25개뿐 아니라 안정적 성공·실패 문항까지 포함한다. FPQ만 회복하고 NFP 오탐도 크게 증가하면 분리 개선으로 선언하지 않는다.
6. 자기보고 확률 AUROC나 사후 문턱 최적화는 하지 않는다. Boolean을 그대로 집계한다. 실제 답변 생성·Well 점수·다른 모델·다른 도메인의 효용은 이 실험 범위 밖이다.
