# 일반 도메인 탐지 연구 방향: GEPA와 내부 표현을 어떻게 비교할 것인가

작성일: 2026-10-02

이 문서는 교수님 제안 이후 논의한 연구 우선순위와 비교 기준을 정리한다. 아래 선행 연구 수치는 원문에서 확인한 보고값이며, 우리 재현 결과가 아니다. 후속 실험은 계획이며, 이 문서 작성으로 새 실험을 실행한 것은 아니다.

## 1. 목표와 우선순위

**최종 목표는 질문의 실제 거짓 전제는 교정하고, 정상 질문에는 불필요하게 반박하지 않는 것이다. 우선 연구할 과제는 거짓 전제의 유무를 구분하는 Detection이다.**

교수님 제안에 따라 CREPE·FalseQA의 일반 도메인 실험을 먼저 구성하고, Cancer-Myth는 이후 확장 대상으로 둔다. 기존 의료 질문 분석은 원인 후보를 제공하지만, 일반 도메인에서도 같은 원인이 작동한다고 가정하지 않는다.

| 과제 | 입력과 출력 | 확인할 것 |
|---|---|---|
| Task 1: Detection | 질문 → 거짓 전제 있음/없음, 필요하면 대상 주장 | 기존 방법보다 FPQ와 정상 질문을 잘 구분하는가? |
| Task 2: Response | 질문 → 최종 답변 | 개선된 탐지가 실제 교정을 늘리고 정상 질문을 보존하는가? |

답변이 좋은 것과 별도 탐지 과제에서 잘 구분하는 것은 같은 측정이 아니다. 두 과제를 연결해 평가하되 수치를 서로 대체하지 않는다.

## 2. 선행 연구에서 확인한 비교 기준

### 2.1 Two Axes: 내부 표현을 이용한 CREPE 탐지

Two Axes의 표 2는 CREPE 탐지 AUROC를 보고한다. 여기서 DiM도 넓게 보면 선형 probe이며, 로지스틱 회귀로 가중치를 학습하는 방식과 구분한 이름이다.

| 모델 | 로지스틱 hidden probe | DiM |
|---|---:|---:|
| Gemma 2 2B-it | 0.70 | 0.74 |
| Qwen2.5-3B | 0.69 | 0.76 |
| Qwen2.5-7B | 0.71 | 0.77 |
| Llama-3.1-8B | 0.73 | 0.74 |
| Qwen2.5-14B | 0.71 | 0.78 |

DiM은 두 라벨 집단의 평균 hidden state 차이로 방향을 정한다. 보고값에서는 DiM이 더 높지만, 일반적인 우월성이나 그 원인까지 입증한 결과는 아니다. AUROC 0.77은 정확도 77%가 아니다.

원문 프로토콜은 길이 300자 이하의 CREPE 질문을 대상으로 한다. 우리 재현에서는 해당 조건과 전체 데이터 평가를 구분해야 한다.

출처: [Two Axes §5·표 2·부록 C](https://arxiv.org/html/2607.08456v1).

### 2.2 Well Actually: GEPA를 적용한 최종 답변

Gemini-3-flash, RAG 없음 조건의 답변 결과다. 아래 값은 논문의 반올림된 S4·S5 비율을 합한 근삿값이다.

| 데이터 | 방법 | FPQ ≥4 | 정상 질문 ≥4 |
|---|---|---:|---:|
| CREPE | Plain | 71% | 100% |
| CREPE | GEPA: FPQ 최적화 | 83% | 86% |
| CREPE | GEPA: FPQ+TPQ 최적화 | 82% | 90% |
| Cancer-Myth | Plain | 29% | 100% |
| Cancer-Myth | GEPA: FPQ 최적화 | 97% | 25% |
| Cancer-Myth | GEPA: FPQ+TPQ 최적화 | 50% | 97% |

**GEPA는 두 데이터 모두에서 유효한 개선을 보였다.** 따라서 “프롬프트로는 안 된다”는 결론은 맞지 않는다. 반면 위 결과만으로 일반 도메인이 해결됐다고 할 수도 없다. FalseQA는 이 논문의 해당 비교 대상이 아니다.

출처: [Well Actually 부록 G, 표 7·22](https://arxiv.org/html/2608.06539v1#A7).

## 3. 우리가 먼저 확인할 질문

**강한 프롬프트 최적화 이후에도 탐지 실패가 얼마나 남으며, 그 실패를 다른 방법으로 줄일 수 있는가?**

GEPA의 유효성을 단독으로 재확인하는 데서 끝내지 않는다. 새 방법이 필요한 지점을 정하기 위해 강한 비교 방법으로 사용한다. 충분히 해결되는 조건에서는 그 결과를 받아들이고, 남는 실패를 중심으로 연구 범위를 좁힌다.

GEPA를 사용할 때는 두 목적을 분리한다.

| 종류 | 최적화하는 출력 | 평가 위치 |
|---|---|---|
| 탐지용 GEPA | 거짓 전제 유무 판정 | 표 1: Detection |
| 답변용 GEPA | 오류 교정과 사용자 질문에 대한 답변 | 표 2: Response |

Well Actually의 좋은 답변 결과가 탐지용 GEPA의 성능을 보장하지는 않는다. 탐지용 GEPA는 별도로 구성하고 평가할 실험이다.

## 4. 내부 표현을 보는 방향도 해결책이 될 수 있다

가능한 가설은 다음과 같다.

> 직접 판정이나 CoT가 틀린 질문에서도, 질문 처리 중의 hidden state에는 라벨을 구분하는 정보가 남아 있을 수 있다. 그 정보를 읽는 방법이 새로운 질문에서도 더 정확하다면 내부 기반 탐지기가 해결책이 될 수 있다.

Two Axes는 내부 방법을 주요 baseline으로 포함할 이유를 제공한다. 그러나 최신 모델의 Direct·CoT나 탐지용 GEPA보다도 내부 방법이 좋다는 것은 아직 확인해야 한다. Cancer-Myth에서 기존 probe가 부족했다는 관찰만으로 CREPE·FalseQA의 내부 방법을 배제하지 않는다.

| 방향 | 하는 일 | 성공을 판단할 근거 |
|---|---|---|
| 내부 정보를 읽기 | hidden state에서 거짓 전제 유무를 예측 | 학습에서 제외한 질문에서 강한 탐지 baseline보다 개선 |
| 내부에 개입하기 | 특정 표현이나 방향을 바꿔 판정을 변화시킴 | 필요한 탐지는 늘리고 정상 질문 오탐은 억제하는 효과 |

우선은 **내부 정보를 읽는 방법의 실제 이점**부터 확인한다. 읽을 수 있는 정보가 있다는 것만으로 “모델이 이미 오류를 판단했다”거나 “그 판단이 답변 과정에서 덮였다”고 결론 내리지 않는다. 개입이 판단을 개선한다는 주장은 추가 실험이 필요하다.

기존 linear probe나 DiM을 다시 적용하는 것 자체는 baseline 재현이다. 우리 기여는 남는 실패를 특정하고, 이를 줄이는 새로운 설계와 일반화 근거에서 나와야 한다.

## 5. 다음 실험의 흐름

### 5.1 먼저 탐지 방법을 공통 조건에서 비교한다

Direct, CoT, 탐지용 GEPA, text classifier, 로지스틱 hidden probe, DiM을 비교한다. LLM 기반 방법은 가능한 한 같은 backbone과 질문 집합을 사용한다. 프롬프트 차이는 각 방법의 구성요소이므로 정확한 원문과 호출 횟수, 추론 설정을 함께 기록한다.

- **데이터:** CREPE와 FalseQA 각각에서 FPQ·정상 질문 라벨, 학습·검증·시험 분할을 먼저 확인한다. 관련 질문이나 수정 쌍이 있으면 서로 다른 분할에 새지 않도록 묶는다.
- **학습과 선택:** probe 학습, GEPA 최적화, layer 선택, 판정 문턱 선택에 시험 문항을 쓰지 않는다.
- **기본 판정:** 각 방법의 기본 Yes/No 또는 classifier 결정에 따른 TP·FN·FP·TN과 탐지율·오탐률을 먼저 보고한다.
- **점수 비교:** 연속 점수가 있는 방법은 AUROC와 같은 오탐률에서의 탐지율도 보조적으로 비교한다. 생성한 이진 판정만 있는 방법에 임의의 확률을 붙여 AUROC를 만들지 않는다.
- **문턱 비교:** 별도 문턱을 사용한 결과는 기본 판정 결과와 구분한다. 시험 자료에서 사후적으로 오탐률을 맞춘 결과는 탐색 분석으로 표시한다.
- **비용:** 호출 수, 추가 생성, 학습·추론 비용을 기록한다. 분류기 학습과 여러 단계 LLM 호출은 필요한 자원이 다르다.

### 5.2 같은 질문에서 방법 간 성공·실패를 연결한다

| 비교 결과 | 확인할 질문 |
|---|---|
| 프롬프트 방법 실패, 내부 방법 성공 | 내부 방법이 어떤 실패를 보완하는가? 주제·문체 단서만 이용한 것은 아닌가? |
| 프롬프트 방법 성공, 내부 방법 실패 | 기존 hidden readout이 무엇을 놓치는가? |
| 둘 다 실패 | 판단 대상, 사실 지식, 질문과 전제의 관계, 라벨 모호성 중 어떤 후보가 남는가? |
| 둘 다 성공 | 실패 집단과 비교할 대조 문항으로 사용할 수 있는가? |

FPQ 미탐과 정상 질문 오탐을 모두 포함하고, 일부 사례만으로 주된 원인을 정하지 않는다. 차이가 반복되는 유형의 빈도와 분모를 보고한다. 이 단계의 행동 차이가 내부 원인을 곧바로 증명하지는 않는다.

### 5.3 개선된 탐지가 최종 답변에도 도움이 되는지 확인한다

탐지 효과를 분리해서 보기 위해 우선 답변 모델과 교정 프롬프트를 고정한다.

> 질문 → 탐지 → 거짓 전제 있다고 판단하면 교정 지시로 답변, 없다고 판단하면 Plain 답변

저장된 Plain·교정 답변을 선택하는 평가를 사용하면 그 사실을 명시한다. 이는 gate 판단에 따라 그 자리에서 새 답변을 생성한 실험과 구분한다.

비교 대상에는 Plain, 항상 교정, 기존 gate, **답변용 GEPA를 항상 적용한 조건**을 포함한다. 탐지 지표가 좋아져도 실제 교정 내용이 부정확하면 답변 효용은 좋아지지 않을 수 있다. 따라서 FPQ 교정과 정상 질문 보존을 함께 평가한다.

## 6. 결과에 따라 선택할 방향

| 확인된 결과 | 다음 결정 |
|---|---|
| 탐지용 GEPA가 강하고 남는 실패가 적음 | 내부 방법을 미리 고집하지 않고, 남는 실패와 비용·전이 문제를 구체화 |
| 내부 방법이 같은 오탐 수준에서 더 많이 탐지 | 어떤 표현을 읽어야 이점이 유지되는지 방법 개발 |
| 서로 다른 문항에서 강점이 있음 | 독립 검증 자료에서 결합의 추가 효용 확인 |
| 모든 방법이 비슷한 문항에서 실패 | 그 문항의 판단 대상·지식·라벨을 통제해 원인 후보 검증 |
| 탐지는 개선됐지만 답변은 개선되지 않음 | gate의 선택과 교정 도구 자체의 실패를 나누어 확인 |

현재 정한 것은 **Detection을 우선하고, GEPA와 내부 기반 방법을 같은 조건에서 비교한 뒤 해결책의 형태를 정한다**는 방향이다. 내부 방법의 우월성, 일반 도메인의 해결 여부, 특정 원인의 확정은 아직 결론이 아니다.

## 7. 실행 설정 확정

사용자와 합의한 생성·탐지 모델은 **GPT-6 Luna (`codex exec`), Claude Sonnet 5.5 (`claude -p`), 기존 Qwen2.5·Qwen3.8·Gemma**다. 답변 채점 및 GEPA 프롬프트 수정 모델은 Sonnet 5.5로 통일한다. 위의 Gemini 수치는 선행 연구 결과이며 이번 실험의 모델 선택이 아니다.

데이터 분할, 공통 프롬프트 전문, 동일하게 통제한 조건과 CLI별로 남는 차이, 실제 소규모 호출 검증 및 실행 명령은 [64번 문서](64_fpqa_datasets_and_gepa_setup_2026-10-02.md)에 정리했다. 전체 성능 평가와 GEPA 최적화 결과는 아직 없다.
