# 전체 문항 검토와 평가 민감도 분석 계획

작성일: 2026-10-01 (Asia/Seoul). 기존 답변·Well 점수·라벨은 변경하지 않는다.
이 문서는 새 검토 결과를 보기 전에 고정한 분석 순서다. 모델·주제별 기존 결과와
AML 등 일부 사례는 이미 읽었으므로 연구자 전체가 맹검이었다고 주장하지 않는다.
새 판정 호출에 라벨·참조·답변·점수를 전달하지 않는 입력 차원의 맹검이다.

## 1. 연구 질문과 이번 작업의 역할

목표는 질문의 실제 거짓 전제는 교정하면서 정상 질문에는 불필요하게 반박하지
않는 것이다. 이번 검토는 새로운 gate의 성능 평가에 앞서, 기존 실패 집계에
모델의 오류, 질문 해석의 모호함, 라벨과 사실의 충돌, 채점 방식의 영향이 얼마나
함께 나타나는지 확인한다. 이들의 인과적 기여율을 합계 100%로 나누지 않는다.

기존 표 1은 질문 단위 판정, 표 2는 최종 답변 평가다. gate 오탐과 낮은 답변 점수는
동일하지 않다. 두 결과를 문항별로 연결하되 각각 따로 집계한다.

## 2. 범위와 순서

| 작업 | 대상 | 호출 여부 | 완료 기준 |
|---|---|---|---|
| A: 질문만 보는 독립 검토 | FPQ 583 + NFP 149 = 732문항 전수 | Terra, 4문항씩 183회 | 732문항 모두 유효한 구조화 출력; 오류 의심은 출처 검증 전 잠정 |
| B: Luna 반복 측정 | 같은 732문항, 기본/보호 지시, 각각 2회 | Luna 2,928회 | 4개 조건×반복 셀의 모든 판정 저장 |
| C: 기존 결과 연결 | 문항 검토 × 네 모델 계열의 기존 gate/답변/채점 | 없음 | 누락·분모·조건 차이 명시한 문항별 표와 집계 |
| D: 평가 기준 민감도 | NFP 새 저점 121답변 + 대조 121답변 | 계획 고정 후 별도 호출 | 프롬프트×판정기 2×2 비교, 원 점수 보존 |
| E: 표현 위치 민감도 | D에서 적격한 최대 40답변 | 별도 호출 | 동일 내용의 앞/뒤 버전 검수 후 대응 비교 |

A/B는 독립적으로 시작한다. C는 A의 1차 판정을 고정한 뒤 연결한다. D/E는 후보와
프롬프트를 고정한 후 실행한다. 새 방법 개발·내부 개입·SFT는 이 작업의 완료 조건이 아니다.

## 3. A: 무엇을 검토하는가

### 3.1 입력과 판정 단위

원문을 그대로 두고 질문 순서를 섞는다. 익명 key만 보내며 FPQ/NFP가 드러나는
원 ID, 라벨, 주석, 이전 의심 표시, 모델 답변·점수는 별도 매핑에만 둔다.
한 질문에 여러 주장이 있을 수 있으므로 질문 하나에 하나의 유형을 강제하지 않는다.
모든 주장에 원문과 정확히 일치하는 인용 구간을 붙인다.

- 주장 종류: 일반 주장 / 개인 상황 / 문의 / 해석 모호.
- 발화 역할: 단정 / 전언 / 전제 / 질문 / 모호.
- 잠정 사실 상태: 오류 의심 / 조건·해석 의존 / 오류 근거를 찾지 못함 /
  질문만으로 확인 불가 / 애초에 단정한 내용이 아님.
- 요청 구간과 남은 모호함을 별도로 기록한다.

개인 상황을 일반 주장으로 바꾸지 않는다. 반대로 개인 서술 속에 명시적으로 들어 있는
인과 추론을 자동으로 보호하지 않는다. 가능성, 필연성, 빈도, 주체, 시점과 전언 출처를
보존한다. 문의는 존재 단정으로 바꾸지 않는다. 흔치 않은 개인 상황은 그것만으로 거짓이 아니다.

### 3.2 의학 근거 검증과 라벨 대조

Terra의 출력은 독립 모델의 선별 결과이며 임상 정답이 아니다. 도구 없이 생성한
의학적 설명이나 모델의 확신을 출처로 취급하지 않는다. 오류 의심 및 조건 의존 주장에는
공식 의학 자료의 URL, 확인일, 관련 근거와 적용 범위를 붙여 후속 검토한다.
개인 진단·예후가 사실인지 외부 자료만으로 확인할 수 없는 경우는 미확정으로 유지한다.
의심되지 않은 항목에도 고정 무작위 표본을 두어 선별 모델이 놓치는 오류를 확인한다.
이 표본의 수와 seed는 후속 판정 전에 별도 manifest에 고정한다.

질문만 본 1차 결과를 고정한 뒤 기존 라벨·참조를 공개한다. FPQ에서는 주석의 목표가
원문에 명시됐는지, 합리적으로 함축되는지, 원문보다 강한 일반화인지, 불명확한지 구분한다.
NFP도 같은 사실·범위 기준으로 검토한다. 기존 라벨을 덮어쓰지 않는다.
연구자의 AI 재독해와 실제 사람/임상가 검토는 동일하게 표시하지 않는다.

## 4. B: 개인 상황 보호 지시와 생성 변동의 구분

과거와 같은 Luna 모델 요청, medium, 시스템 지시, JSON 출력, 문항당 독립 세션,
240초 제한을 재사용한다. 단, 현재 서비스가 같은 backend snapshot이라는 보장은 없다.
과거 실행은 참고 비교이며 새 두 조건의 동시기 비교를 주분석으로 한다.

두 무작위 블록에서 매번 732문항×두 조건을 섞어 실행한다. 도구·참조·라벨·이전
검토문은 주지 않는다. 두 반복은 변동을 탐색하기 위한 최소 설계이며 확정적 안정성 보장이 아니다.

- 같은 조건 반복 간 불일치율과 Yes→No / No→Yes를 라벨별 집계한다.
- 각 반복의 기본→보호 지시 변화와, 두 반복에서 공통으로 바뀌는 문항을 집계한다.
- TPR, FPR, TPR−FPR와 변화량을 보고한다. 질문의 모든 조건·반복 결과를 묶어
  라벨별 대응 부트스트랩을 수행한다. 동일 문항과 주제 그룹의 종속성도 한계에 기록한다.
- 자기보고 확률은 원자료에 보관하지만 AUROC를 표 1의 주 수치로 사용하지 않는다.
- 변화가 유의하지 않다는 것을 효과가 0이라는 증거로 표현하지 않는다.
- 변동 건수를 지시 변화 건수에서 단순히 빼서 '순수 지시 효과 건수'라 부르지 않는다.

## 5. C: 무엇이 실제 실패인지 연결

원문·주석 → 모델의 판단/답변 → 실제 지적 대상 → 근거 → Well 이유를 같은 문항에
연결한다. Direct에 이유가 없으면 이유 미상으로 둔다. 별도 Review를 그 판단의
원인으로 대신 사용하지 않는다.

NFP의 새 저점 121건(79문항)은 다음처럼 재검토한다. 복수 문제는 중복 기록한다.

1. 실제 오류를 타당하게 교정했지만 벤치마크에서는 감점됨.
2. 개인 상황을 일반화하거나 원문에 없는 주장을 만들어 잘못 반박함.
3. 원문 주장을 그대로 읽었지만 진위·범위 판단이 부정확함.
4. 타당한 부연인지 반박인지 행동 코딩과 Well 해석이 충돌함.
5. 답변 유보·비응답 등 별도 문제 또는 판단 불가.

FPQ도 목표를 놓친 경우, 다루지만 충분히 교정하지 않은 경우, 교정 후에도 원래
가정에 따라 답하는 경우, 타당한 답변과 평가가 충돌하는 경우를 구분한다.
목표 언급이나 관련 지식의 등장만으로 '모델이 오류를 알고 있었다'고 결론내리지 않는다.

원래 표 1·2를 그대로 보고하고, 주장 유형·근거 상태별 TPR/FPR와 Well 평균,
≥4, 5점 비율을 보조 분석으로 제시한다. 모델·방법별 분모와 결측을 따로 표시한다.
'오류 근거 없음'과 '임상적으로 참이 검증됨'을 같은 집단명으로 쓰지 않는다.
어떤 비율이 20%를 넘는지에 따라 유리한 문항만 제외하는 규칙은 사용하지 않는다.
모호한 문항을 포함/제외한 민감도 결과를 모두 제시한다.

## 6. D/E: 평가 측정의 구분

### 채점기와 프롬프트

121개 손실 답변과 같은 모델·방법을 우선 맞춘 121개 비손실 답변을 고정 seed로
선택한다. 비손실 대조는 조건이 달라질 수 있으므로 원 점수와 대상 분포를 공개한다.
이 선택 표본의 결과를 전체 답변의 오류율로 일반화하지 않는다.

원래/라벨 안내 제거 프롬프트 × Sonnet/비Sonnet 판정기를 교차한다.
두 효과를 한꺼번에 바꾼 비교만으로 어느 요소가 원인이라고 말하지 않는다.
같은 답변의 원문 hash를 고정하고, 원 평가 점수와 새 점수를 별도 보관한다.
라벨 안내 제거만으로 라벨을 전제한 나머지 rubric까지 중립화되는 것은 아니므로
프롬프트 차이를 정확하게 공개하고 '사실 정확도 정답 평가'라고 부르지 않는다.
점수 차이·≥4 전환·반박 여부 판단의 일치도를 함께 보고하며 κ만으로 타당성을 판정하지 않는다.

### 문장 위치

최대 40개 적격 답변에서 동일한 교정·안내 내용을 앞/뒤로 이동한다. 문장 순서 외의
내용은 바꾸지 않고 지시어·논리 연결이 깨진 경우 제외 사유를 기록한다. 강한 반박이나
부연이 특정 위치에 몰린 자연 답변의 상관과, 통제된 위치 효과를 구분한다.
이는 판정기의 위치 민감도를 확인하는 실험이며 생성 모델의 내부 오류 원인 실험이 아니다.
실제 사람의 점수 보정은 별도 확보한 경우에만 인간 검토라고 보고한다.

## 7. 결과별 논문 해석

- 문항의 실제 오류를 고친 감점이 많으면: 원래 NFP 점수를 불필요한 반박의 직접 측정으로
  쓰는 해석을 제한하고, 근거 상태별 결과를 병기한다. 데이터 전체가 무효라고 결론내리지 않는다.
- 문항 근거를 통제해도 잘못된 반박이 반복되면: 모델의 해석/판정 실패를 중심으로 다음
  원인 실험을 설계한다. 동일 현상이 여러 모델에서 반복되는지 확인한다.
- 채점 조건에 따라 결론이 바뀌면: 평가 민감도를 주 결과의 한계로 보고한다.
- 보호 지시 변화가 반복 변동을 넘고 특정 주장 유형에서 일관되면: 유형별 행동 변화의
  근거로 사용한다. 내부 메커니즘이나 임상적 최적 정책의 증거로 과장하지 않는다.

## 8. 실행과 상태 확인

실행 코드: `scripts/run_measurement_audit_20261001.py`.
준비 및 결과 루트: `results/audits/measurement_validity_20261001_v1/`.
`questions/`와 `luna_repeats/`에 각각 plan, blind_inputs, private_mapping,
jobs, preflight, status 및 호출별 원문 로그가 저장된다.
익명 매핑과 검토 결과는 모델 입력과 분리한다. 기존 자료는 읽기만 한다.

```bash
python3 scripts/run_measurement_audit_20261001.py audit \
  --out-dir results/audits/measurement_validity_20261001_v1/questions --workers 4
python3 scripts/run_measurement_audit_20261001.py repeat \
  --out-dir results/audits/measurement_validity_20261001_v1/luna_repeats --workers 4
```

각 실행은 고유 output lock을 사용한다. STOP 파일이나 첫 실패가 있으면 중단한다.
실패 응답은 숨기거나 정상 응답으로 대체하지 않고, 자동 재시도나 무기한 대기를 하지 않는다.
완료 여부는 status.json과 검증된 호출 수로 확인한다. 준비·실행 시작·전수 완료·출처 검증
완료는 각각 다른 상태로 보고한다.
