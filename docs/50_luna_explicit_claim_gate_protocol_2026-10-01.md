# Luna: 검토 대상·간단한 근거·최종 판정을 함께 출력하는 진단

작성: 2026-10-01. [49번 전환 문항 분석](49_luna_stable_switches_and_causal_candidates_2026-10-01.md)의 후속으로 사용자가 전체 실행을 요청했다. **새로운 구조화 판정 과제**이며, 이전 Direct의 내부 생각이나 과거 판정 이유를 복원하는 실험이 아니다. 이 문서는 실행 규약이며 완료 결과표는 아니다.

실행 후 1,455개 유효 출력과 9개 형식 오류를 확인했다. 동일 문항 723개의 비교와 사례 분석은 [51번 결과 문서](51_luna_explicit_claim_gate_results_2026-10-01.md)에 기록했다.

## 범위

| 항목 | 고정 조건 |
|---|---|
| 모델 | `gpt-5.6-luna`, reasoning medium, CLI 명시 요청과 preflight banner 확인 |
| 문항 | 평가 문항 732개: FPQ 583 + NFP 149 |
| 조건 | 기본 Direct의 보호 문구 없음 / 기존 개인 상황 보호 문구 전체 유지 |
| 호출 | 문항·조건마다 독립 1회, 총 1,464회; 스모크 4문항×2조건도 동일 실행에 포함 |
| 실행 | 도구 사용 없음, 호출당 240초, 출력 토큰 별도 제한 없음, 12개 병렬·nohup |
| 모델 입력 | 원 질문과 해당 조건 지시만. 라벨·ID·주석·이전 판정·이전 답변 비공개 |
| 출력 | 검토한 주장 목록과 최종 질문 수준 판정, 짧은 근거 |
| 기존 비교 | 같은 732문항의 기본/보호 Direct 각 2회 기록 |

두 조건의 추가 구조화 지시는 같다. 질문 순서는 seed 20261001로 섞고, 조건 호출 순서는 문항마다 번갈아 배치한다. 조건별 전체 실행을 시간상 앞뒤로 완전히 분리하지 않는다.

## 출력 필드

```json
{
  "examined_premises": [
    {
      "question_quotes": ["질문에서 그대로 인용한 구절"],
      "claim": "검토한 주장 한 문장",
      "assessment": "false | supported | undetermined",
      "reason": "해당 판정의 짧은 근거 1~2문장"
    }
  ],
  "has_false_premise": false,
  "false_probability": 0.0
}
```

실제 출력은 영어다. 오류라고 본 주장뿐 아니라 검토했지만 오류라고 보지 않은 주장도 기록하도록 한다. 관련 전제를 찾지 못하면 빈 목록을 허용한다. 긴 사고 과정은 요구하지 않는다. 자기보고 확률은 기존 형식과의 연속성을 위해 유지하지만 AUROC로 보고하지 않는다. 최종 탐지 집계는 boolean을 사용한다.

질문에 근거를 인용하도록 하는 것, 주장을 명시하도록 하는 것, false/supported/undetermined로 나누는 것 자체가 원 Direct와 다른 과제다. 따라서 성능 변화가 나타나도 ‘설명 한 문장을 추가했기 때문’으로 단일 귀속하지 않는다. 개인 진단을 supported로 받아들일지 undetermined로 둘지도 관찰 대상이며 사후에 통일하지 않는다.

## 보존과 검사

- 원 prompt, JSON 이벤트, stderr, 최종 출력, 파싱 결과, 호출 시간, 토큰 usage를 문항별로 저장한다.
- 원문 인용 불일치는 표시하고 그대로 보존한다. 의미를 바꾸는 자동 보정이나 좋은 결과만 고르는 재생성은 하지 않는다.
- 주장 판정과 최종 Yes/No의 불일치를 오류로 삭제하지 않는다. 예: 전부 undetermined인데 최종 Yes.
- boolean과 자기보고 확률의 지정 규칙 불일치도 별도 표시한다.
- JSON 스키마 실패는 실패 건수로 남긴다. 인증·한도·전송 문제는 진행을 중단하고 완료된 결과를 보존한다.
- STOP 파일이 있으면 실행하지 않는다. 완료 레코드는 재호출하지 않는다.

## 완료 후 볼 것

1. 기본/보호 각각에서 FPQ·NFP 최종 Yes/No 수와 유효 분모.
2. 이전 Direct의 각 반복과 새 판정 사이의 전이. 과거 두 번이 일치한 문항과 불일치한 문항을 구분한다.
3. 같은 질문에서 검토 대상의 인물·시점·출처·강도가 조건에 따라 달라지는지.
4. 같은 대상을 유지했는데 예외·불확실성·모순 중 무엇을 근거로 판정했는지.
5. 개별 주장 판정과 최종 질문 판정의 일치 여부.

3~5는 출력에 나타난 설명의 분석이다. 그 설명이 실제 내부 계산의 충실한 기록이라는 보장은 없다. 새 구조화 과제의 근거를 과거 Direct의 이유로 소급하지 않는다. 이전 실험과 실행 시점도 달라 과제 차이와 생성 변동이 섞일 수 있다. 임상 정확성이나 원 주석의 타당성은 별도 검토 사항이다.

기존 보호 문구의 범위 보존/예외 처리 조항을 분리한 A/B 요인 실험은 이번 실행에 포함하지 않는다. 이번에는 먼저 두 기존 조건에서 모델이 보고하는 검토 대상과 근거를 확보한다.

## 실행 위치

```text
results/frontier_cli/luna_explicit_claim_gate_20261001_v1/
  plan.json                       정확한 prompt·설정·입력 해시
  preflight.json                  요청 모델 확인
  historical_repeat_items.csv     비교할 기존 판정 동결본
  run.log / run.pid               nohup 로그·PID
  status.json                     진행 및 판정 전이 집계
  decisions_and_claims.csv         완료된 응답의 주장·근거·판정
  baseline/<id>/record.json        문항별 기록
  context_rule/<id>/record.json    문항별 기록
```

실행 코드는 [run_luna_explicit_claim_gate_20261001.py](../scripts/run_luna_explicit_claim_gate_20261001.py)이며, 기존 서버의 Luna CLI transport 모듈과 인증을 재사용한다. 새로운 도구/모델 설치나 GPU 작업은 없다.

```bash
python3 scripts/run_luna_explicit_claim_gate_20261001.py \
  --out-dir results/frontier_cli/luna_explicit_claim_gate_20261001_v1 \
  --workers 12
```

진행 중에는 같은 명령을 중복 실행하지 않는다. 출력 잠금 파일로 중복 쓰기를 막는다. 최초 nohup 셸 실행은 진행 상태에 도달하지 않아 종료됨을 확인한 뒤, 같은 nohup 명령을 독립 세션으로 다시 시작했다. 모델 호출 기록이 없는 시작 실패였으며 정상 완료된 스모크 8회는 재사용했다.
