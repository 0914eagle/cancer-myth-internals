# 26. 무엇을 발견했고, 왜 멈추거나 바꿨는가

교수님께 설명할 순서의 원고와 실제 질문·답변 인용은 [28](28_advisor_progress_narrative.md). 이 문서는 실험 이력의 수치·출처를 보존한다.

작성: 2026-09-15. 이 문서는 실험 이력과 의사결정의 현재 통합 기록이다. 새 방법 후보는 [27](27_method_candidates_and_tests.md), 서버 실행 명세는 [25](25_baseline_suite.md)를 함께 읽는다. 이전 계획 문서의 “다음 실행”, 모델 순서, 표 번호, 판정기 확정 표현이 이 문서와 충돌하면 이 기록의 상태 구분을 우선한다. 과거 결과 파일과 프로토콜은 수정하지 않는다.

## 0. 현재 위치와 출처 수준

**확보한 것은 baseline의 행동 차이, 평가·생성 설정의 문제, 제한된 게이트/steering 진단이다. 내부 게이트의 우위나 선택적 steering의 최종 효과를 입증한 상태는 아니다.** 현재 Qwen2.5-7B-Instruct의 생성 baseline을 진행하고 있으며, 새 방법은 후보 단계다.

| 표기 | 증거의 종류 | 해석 범위 |
|---|---|---|
| 원본 보고서 확인 | 사용자가 전달한 로컬 report 파일을 직접 읽음 | 보고서의 집계 확인. 전체 서버 task ledger를 독립 재실행한 것은 아님 |
| 사용자 로그 | 대화에 붙인 서버 콘솔·후속 요약 | 표시된 값의 기록. 원본 run identity·개별 행 재검증은 미완료 |
| 저장소 과거 기록 | 기존 문서의 결과 | 당시 조건·정렬·판정기 한계를 함께 계승 |
| 계산 | 표시된 개수에서 산술적으로 도출 | 새 모델/판정 호출 아님 |
| 후보 | 논의·설계만 존재 | 구현·실험·효과를 확보한 것으로 쓰지 않음 |

이번 문서화에는 GPU 추론, GPT 판정, pytest/torch 실행이 없다. 원본 Quick45/overnight 보고서 사본과 해시는 [출처 기록](reviews/progress_2026-09-15/source_manifest.json)에 보존한다. Qwen gate·길이 점검·현재 진행률은 사용자 로그에 근거한다. 실시간 서버 상태를 조회한 것은 아니다.

## 1. 초기 E1: 내부 신호는 보였으나 곧바로 게이트·C의 근거가 되지 않았다

출처: [E1 원 기록](experiments/01-e1-prediagnostic.md). 아래는 새 Qwen suite가 아니라 초기 다중 모델 실험이다.

| 항목 | Llama-3.1-8B | Qwen2.5-7B | Gemma-2-27B |
|---|---:|---:|---:|
| 당시 Plain PCR | 3.4% (20/585) | 5.6% (33/585) | 약 9.4% (55/585) |
| 전제 구간 최고 probe AUROC | .815 | .812 | .803 |
| 질문 끝/마지막 prompt 위치 | .73/.72 | .74/.71 | .70/.70 |
| 생성 전 Plain PCR 예측의 일부 최고 셀 | .847 | .823 | .859–.878 |

**발견과 제한.** 자연적으로 교정한 답변이 적어 성공 집단이 특정 문항·카테고리에 치우칠 위험이 있었다. 질문 전체 TF-IDF가 .771 [ .73, .81 ]로 마지막 위치 probe보다 높았다. 이 결과는 텍스트 대조가 필요하다는 근거이며 “문체 때문에 텍스트만 부풀었다”는 확정 증거가 아니다.

전제 정렬은 초기 585개 중 LLM 294 / heuristic 225 / 없음 66이었다. heuristic 확인 표본 6/6에서 잘못된 구간을 잡았다는 감사가 있어 초기 구간 AUROC .80–.82에는 그 오류가 섞여 있다. 따라서 “구간 .8 대 마지막 .7이므로 정보 통합이 실패한다”는 해석은 아직 가설이다. 당시 D의 .82–.88도 **Plain 성공 예측**이지 FP 개입의 구제·피해 예측 성능이 아니다.

**변경.** 같은 질문의 기존 +1/−1 참조 답변으로 paired C를 구성하고, 이후 교수님 지시에 따라 Gemma 한 모델의 간단한 baseline·개입 파일럿으로 범위를 좁혔다. AO/NLA/SAE와 큰 모델 전체 격자는 당장의 필수 실행에서 제외했다. 사용할 수 없어서가 아니라 baseline과 방법 필요성을 먼저 확인하기 위해서다.

**개수 정정.** E1의 “232개 질문에 양쪽 참조 존재”는 당시 참조 후보 풀에 관한 기록이다. 이후 fit 제한과 선택을 거친 overnight의 실제 완전한 참조 쌍은 **135개**다. 두 수를 같은 학습 실행의 분모로 쓰지 않는다. 저자 균형을 시도했다는 것과 양·음 저자가 완전히 같다는 것도 다르다(§7).

초기 GPT-4o/Codex 비교에서는 450건의 3-way 일치가 58.2%, κ=.28이었다. 이는 판정기 변경의 영향이 크다는 경고다. “Codex가 의사보다 엄격하다”, “세 모델의 순위가 같으므로 모든 방법 순위도 보존된다”, “Codex 호출은 비용이 없다”는 과거 해석은 사용하지 않는다.

## 2. Gemma baseline: 교정 지시는 효과가 있었지만 평가가 먼저 흔들렸다

모델 Gemma-2-9B-it, grouped manifest: fit FPQ 349/NFP 89, dev 117/30, test 117/30. 합계 732개이며 원 명목 585+150=735에서 충돌 질문·few-shot 제외를 적용한 실행이다. NFP와 Well TPQ는 같은 정상 질문에 대한 다른 주석이며 150+150=300개가 아니다. fit은 전체 모델 finetuning만을 위한 분할이 아니라 probe·C·보정용 자료다.

분할은 StratifiedGroupKFold 5개 fold 중 test/dev를 고정한 holdout 실행이다. 이 결과는 5개 fold 모두의 독립 평가를 완료한 결과가 아니다.

### 2.1 최초 Sol 평가

출처: [NFP baseline 기록](reviews/nfp_baselines_2026-09-14.md), 사용자 서버 표. PCR/NFP는 %, PCS는 −1~1. 정상 지표는 일반 의료 QA 정확도가 아니다.

| 방법 | PCR [95% CI] | PCS | NFP [95% CI] | FPQ rescue/harm | NFP rescue/harm |
|---|---|---:|---|---|---|
| Plain | 6.0 [2.3,10.2] | −.718 | 63.3 [46.7,80.0] | 0/0 | 0/0 |
| FP Identification | 59.0 [51.3,67.3] | .410 | 30.0 [13.3,46.7] | 64/2 | 1/11 |
| Premise CoT | 34.2 [26.4,42.7] | −.162 | 53.3 [36.7,70.0] | 34/1 | 2/5 |

**실시 내용:** Plain은 직접 답변, FP Identification은 Yes/No 판별 뒤 조건부 교정 답변, Premise CoT는 전제 검토문 뒤 최종 답변이다. 이 당시 CoT를 일반적인 “Let's think step by step” 하나와 동일시하지 않는다.

**관측.** FP 지시는 117개 중 성공을 7개에서 69개로 늘렸지만 정상 지표는 낮아졌다. CoT도 40/117을 성공으로 판정받았다. 따라서 prompting은 아무 효과가 없다는 서사는 폐기해야 한다. 다만 다음 판정 문제 때문에 이 표를 최종 trade-off 증명으로 삼지 않았다.

### 2.2 α=0이 드러낸 문제와 중단 이유

| L14 조건 | PCR | PCS | NFP |
|---|---:|---:|---:|
| Plain | 6.0 | −.718 | 63.3 |
| α=0 | 6.0 | −.709 | 53.3 |
| α=.02 | 6.0 | −.735 | 56.7 |
| α=.05 | 5.1 | −.709 | 50.0 |
| α=.1 | 7.7 | −.675 | 53.3 |

**사용자의 파일 비교**에서 Plain과 α=0의 FPQ 117개·NFP 30개 답변 텍스트는 모두 같았다. 그런데 정상 판정은 4개가 성공→실패, 1개가 실패→성공으로 바뀌어 총 5/30개가 뒤집혔다. 합계 19/30→16/30이다.

**왜 멈췄나.** 작은 α 효과와 judge 변동을 구분하기 어려웠고 설정마다 147개 재채점이 반복되어 Sol 사용량도 커졌다. L21 α=0 채점 중 사용자 중단 기록이 있으며 전체 sweep 완료로 쓰지 않는다. L14만 보고 steering 일반의 실패를 선언하지도 않는다.

**무엇을 바꿨나.** 같은 질문·참조·답변·judge 프로토콜인 판정 입력을 공유하고, 저장 원문 재파싱과 호출 수 제한을 도입했다. 이후 새 판정은 Terra를 기본으로 삼되 Sol 점수를 덮어쓰지 않는다. 서로 다른 프로토콜 사이에는 캐시를 공유하지 않는다.

## 3. NFP 판정: 형식 문제와 평가 대상 혼동을 나눠 해결했다

### 3.1 진단 결과

출처: [Terra v1 해석](reviews/terra_nfp_check_v1_interpretation.md), [23](23_gemma_steering_pilot.md), 사용자 v2·balanced 콘솔.

| 단계 | 수치 | 의미·다음 행동 |
|---|---|---|
| Terra v1 최초 파싱 | valid 3/20, invalid 17 | 모델 실패율로 확정하지 않고 raw 응답 확인 |
| v1 재파싱 | valid 20/20, 기준 일치 16/20, 반복 일치 6/10 | 형식 복구와 의미상 오판정은 다른 문제 |
| 역할을 명확히 한 v2 | valid 20/20, 기준 일치 20/20, 반복 일치 10/10 | 이미 본 모두 +1 표본에서의 개선; 일반 정확도 아님 |
| 별도 5 정상+5 과교정, 각 2회 | 사용자 로그상 20/20 기준 일치 | 무조건 +1 방지용 소규모 점검. 보류 6개와 기준 라벨 한계 존재 |

v1의 오감점 이유는 “대안을 설명하지 않았다”, “모든 환자가 해당 치료를 받는 것은 아니라고 반박하지 않았다” 등의 부재였다. 원래 NFP에서 보려던 것은 **답변이 질문에 없는 거짓 전제 지적을 만들어냈는가**였다. 이를 “환자에게 더 반박했는가”로 잘못 읽은 사례를 발견했다.

v2는 Possible hallucination이 필수 교정 정답이 아님을 명시하고, 개별 진료 상황을 모든 환자에 대한 주장으로 바꾸지 말며, 실제 부당한 지적의 답변 근거를 요구했다. 이 변경은 별도 프로토콜이다. 독립 임상 전문가 검증이 완료된 판정기로 부르지 않는다.

### 3.2 같은 baseline의 NFP가 바뀐 이유

| 방법 | 최초 NFP, Sol 원 지침 | NFP, Terra v2 | FPQ, 기존 Sol PCR |
|---|---:|---:|---:|
| Plain | 19/30 = 63.3 | 30/30 = 100 | 7/117 = 6.0 |
| FP Identification | 9/30 = 30.0 | 18/30 = 60 | 69/117 = 59.0 |
| Premise CoT | 16/30 = 53.3 | 30/30 = 100 | 40/117 = 34.2 |

**발견.** FP Identification의 정상 질문 손실은 두 판정에서 모두 보였고, CoT의 손실은 v2에서는 사라졌다. 그러나 판정 모델과 지침을 함께 바꿨으므로 원인을 prompt 하나 또는 모델 하나로 분리할 수 없다. 30/30은 전체 답변의 의료적 정확성·안전성을 뜻하지 않는다. dev 안에 지침 개발 문항도 있다.

**왜 또 평가를 바꿨나.** 원 참조 대상 지적, 참조 밖 일반 과교정, 답변 회피, 추가 의학 오류가 한 숫자로는 구분되지 않았다. 그래서 원 결과는 유지하고 더 넓은 답변 품질을 다루는 Well 평가를 새 suite의 별도 기준으로 준비했다. Well의 낮은 점수를 전부 과교정으로 읽지도 않는다. 최신 방식은 [25](25_baseline_suite.md).

v3/FPQ evidence 초안은 REVIEW/null·근거를 포함한 별도 감사 설계다. 이것이 원 PCR을 대체하거나 새 suite 전체에 자동 적용된 것으로 쓰지 않는다. parser fallback +1과 예시 참조 주입 등 구현 문제는 평가 규칙과 구분해 기록했다([12 §15](12_discussion_decisions.md#15-2026-09-14--파일럿-진행-확인과-두-가지-정정)).

### 3.3 FPQ에도 같은 문제가 있는지 먼저 확인했다

[점수별 선정 FPQ 18답변 검토](reviews/fpq_18_sol_comparison_2026-09-14.md)에서는 초안을 고정한 뒤 기존 Sol과 대조했다. 명확히 비교할 수 있는 10답변(정확 교정 후보 5, 부분 교정 2, 미교정 3)은 모두 기존 +1/0/−1과 대응했다. 나머지는 표적 교정과 추가 오류가 분리되는 1개, 귀속·점수 경계 보류 7개였다. 18답변에는 같은 질문의 서로 다른 방법이 포함되므로 18개 고유 질문이라고 하지 않는다.

이것은 대표 표본의 판정 정확도 10/10을 뜻하지 않지만 **NFP에서 발견한 역할 혼동을 FPQ 판정 전체의 실패로 확대할 근거도 얻지 못했다.** 그래서 FPQ 전체를 즉시 새 judge로 교체하지 않고 기존 점수를 보존하면서 게이트 replay를 진행할 수 있었다.

선정 metadata의 전체 dev 분포는 Plain −1/0/+1 = 91/19/7, FP = 21/27/69, CoT = 59/18/40이다. 따라서 CoT의 0점 18개는 구체적인 후속 검토 대상이 됐다.

## 5. CoT 감사: 탐지·교정·평가 문제를 분리할 필요를 발견했다

### 5.1 기존 0점 18개에서 review 128→1024를 먼저 확인

사용자 제공 `cot_review_1024.md`의 원본 요약을 확인했다([요약 사본](reviews/progress_2026-09-15/cot_review_budget_excerpt.txt)). 기존 0점 FPQ 18개를 대상으로 모델·prompt·final 512를 유지하고 review cap만 바꿨다. **검토문 12/18, 최종 답변 12/18이 바뀌었고 새 review의 cap 도달은 0개**였다. GPU 생성은 했지만 GPT 채점은 0회이고 새 PCR은 없다.

이 결과는 검토 예산이 실제 pipeline 출력에 영향을 준다는 뜻이다. 출력이 바뀐 12개가 모두 개선된 것은 아니며, 0점 사례만 선택했으므로 전체 CoT 성능 증가율을 계산하지 않았다. 이후 Quick45에서 같은 판정기로 두 길이를 비교했다(§6). 이 18개와 아래 귀속 검토 18개는 **다른 선정 집합**이다.

### 5.2 기존 +1 40개도 함께 읽었다

기존 Sol +1 40개를 읽은 [감사 원본](reviews/cot_positive40_2026-09-14/summary.md):

| 검토 우선순위 | 개수 | 결론이 아닌 것 |
|---|---:|---|
| 핵심 교정 지지 | 19 | 전체 답변의 의학적 정확성 인증 아님 |
| 답변 품질·교정 정도 재검토 | 3 | 확정된 틀린 반박 3개라는 라벨 아님 |
| 질문·참조 해석 우선 확인 | 18 | 확정된 오류 주석 18개라는 뜻 아님 |

40개 중 18개(45%)가 귀속 확인 대상이어서, 단순히 모델이 참조를 반박했는가만 읽기 어려웠다. 조건부 표현을 필연으로, 개별 의사 판단을 모든 환자의 주장으로 읽는 문제가 쟁점이었다. 이 비율은 성공 사례만 선택한 감사의 비율이며 전체 데이터 오류율이 아니다. 원 PCR 40/117을 19/117로 바꾸지 않는다.

외부 AI의 두 단계 검토도 완전한 맹검이나 임상 확정이 아니다. 원 5/13/0 문항 판정은 보존했고 후속 이견·참조 정박·자료 미열람을 기록했다([회신 대조](reviews/external_ai_attribution_18_v1/followup_2026-09-14/report.md)). 원 참조 목표 19개에 대한 귀속 8/8/3 같은 집계는 문항 18개 집계와 다르다.

**방향 변경.** 평가 감사만 계속하면 방법 실험이 멈추므로, 원 Cancer-Myth 지침으로 작은 비교를 먼저 재개하고, 다음 큰 suite는 Well의 명시된 답변 지침을 별도 버전으로 사용하기로 했다. 선행 prompt를 쓰는 것은 비교 근거이지 판정 오류가 없다는 보장이 아니다.

## 7. Overnight: 방향·강도·위치를 나눠봤지만 S는 정확 교정 지표가 아니었다

출처: [원본 보고서 사본](reviews/progress_2026-09-15/overnight_report.txt), [실행 프로토콜](experiments/overnight_c_diagnostics.md). 물리 GPU 0·1. 9시간은 상한이며 실제 보고된 경과는 **2,962.3초, 약 49.4분**. 1,144/1,144 complete, 실패/timeout/skipped/pending 0. GPT 0회. 생성 작업 380 = fit 64×2 + dev 18×14. 생성 외 작업은 dose 732, extract 2, project 30이다.

### 7.1 C를 실제로 어떻게 만들고 적용했나

- 기존 방향: fit에 속한 완전한 참조 쌍 135개, 같은 질문의 +1 응답−−1 응답을 Gemma에 teacher forcing. 첫 32토큰 평균 차를 문항 평균하고 unit norm으로 정규화.
- 재추출: 같은 참조 쌍의 첫32/전체 답변, L14/21/28. 기존 첫32와 재추출 cos=1.0000.
- 자기 모델 방향: fit FPQ 64개에서 Plain과 **항상 FP_CORRECT 지시** 답변을 생성, 첫32/전체 평균 차. Yes/No 조건부 FP Identification 전체 파이프라인이 아니며 새 정확성 판정 없음.
- 적용: `h' = h + α s_l u_l`. `s_l`은 fit 질문 마지막 prompt 출력 norm 평균(L14 154.4064, L21 331.8292, L28 527.3159). α=.1은 매 토큰 norm을 정확히 10% 바꾸는 규칙이 아니다.
- 축 제거: `h' = h − (h·u)u`. 양쪽 성분을 제거하므로 순응만 제거했다고 하지 않는다. prefill/first32 predictor/all 위치와 무작위 방향 3개도 비교.

저자 구성의 실제 차이는 +참조 Gemini 57/135 대 −참조 18/135, GPT-3.5 4 대 19, MDAgents 4 대 23이다. 균형 선택 시도 후에도 차이가 남았다. 이것은 교란 가능성이지 문체 원인 확정은 아니다.

### 7.2 확률 곡선과 자유 생성에서 무엇을 봤나

S는 `mean log p(+참조) − mean log p(−참조)`다. 아래 원 C L21 all은 같은 24쌍의 α=0 대비 변화이고, cap은 별도 dev 생성 18개의 수다. 두 패널이 같지 않아 문항별 인과 대응으로 읽지 않는다.

| α | ΔS | Δ +참조 logp | Δ −참조 logp | 생성 512 cap |
|---|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | 6/18 |
| .1 | .0146 | −.0236 | −.0382 | 6/18 |
| .3 | .0407 | −.2024 | −.2430 | 10/18 |
| .6 | .1100 | −1.1476 | −1.2576 | 18/18 |

**발견.** ΔS가 커져도 교정 참조 자체의 확률은 낮아졌다. 실패 참조가 더 많이 낮아져 차이가 커질 수 있었다. 높은 강도에서 출력 cap도 늘었다. cap 자체는 퇴화·오답 확정이 아니지만 출력 검토가 필요한 경고다. 따라서 “S 상승=교정 개선”, “S가 평평하면 방향이 틀림”을 선택·기각 규칙으로 사용하지 않는다.

| 새 C, L21 all | α | 생성 cap | 원 C와 cos |
|---|---:|---:|---:|
| 참조 전체 | .3 | 0/18 | .6099 |
| Gemma 지시 차 첫32 | .3 | 7/18 | −.0240 |
| Gemma 지시 차 전체 | .3 | 12/18 | .2440 |

이는 길이·방향 차이이지 정확 교정률 순위가 아니다. 새 생성 답변에 검증된 PCR은 아직 없다. 원 C에 Plain 답변을 투영한 AUROC는 첫32 .7619/전체 .9643이지만 +1이 4개, −1이 21개이며 0점 5개를 제외한 **답변 후 표상** 분석이다. 질문 단계 gate 성능이나 인과적 제어 증거가 아니다.

**무엇을 바꿨나.** 외부 저자 교란을 줄이려 자기 모델 대조를 만들었지만, 이번에는 정확 교정 성공 선별이 없다는 한계를 명시했다. 다음 후보는 같은 모델·같은 질문·확인된 성공/실패를 결합한 C, 또는 그 출력 선호를 직접 학습하는 C다. 기존 실험을 폐기하지 않고 비교군으로 남긴다.

## 8. 새 Qwen suite: 질문 판별과 답변 평가를 분리했다

모델 Qwen2.5-7B-Instruct로 전환했다. 선행 연구와 모델을 겹치게 하고 baseline 구성을 명확히 하기 위한 선택이며, Gemma 실패를 피해 유리한 모델만 선택했다는 효과 주장을 하지 않는다. 모델만 같아도 split·prompt·judge·출력 예산이 다르면 선행 수치를 직접 채울 수 없다.

Well 공개 당시 train/dev/test ID를 복원하지 못했으므로 현재 grouped manifest를 유지했다. 이번 사용자 실행은 732문항. 고정 prompt baseline은 전체에 생성할 수 있지만 probe/GEPA/finetuning은 학습·보정·평가 분리가 필요하다. GEPA/finetuning은 이번 자동 실행에 없다.

| 생성 코드명 | 실제 수행 | 판별 실험과의 차이 |
|---|---|---|
| plain | 질문 직접 답변 | 판별 없음 |
| zero_shot_cot | 일반 step-by-step 추론 뒤 최종 답변 | 전제 전용 검토와 다름 |
| fp_identification | 질문 Yes/No → 교정 지시 또는 Plain | 파이프라인 자체의 내부 선택 포함 |
| extract_verify | 전제 추출 → 사실 판별 → 답변 | 현재 RAG 없음 |
| premise_review | 전제 검토문 → 답변 | 과거 premise_cot 계열 |

Well-inspired adaptation이며 생성 단계까지 원 논문의 정확 재현이 아니다. Well 답변 평가 템플릿은 별도로 보존하지만 판정 모델은 Terra이므로 출판값 재현 주장도 하지 않는다. 현재 사용자가 보고한 큰 suite의 최종 Well 점수는 아직 없다.

### 8.1 생성이 끝나기 전에 CPU gate를 병행했다

질문 prefill 732개가 완료되어, 생성 결과 없이 holdout dev 판별을 실행했다. 입력은 질문뿐이며 L11/17/22 후보를 비교했다. 아래는 **Qwen**, §4는 **Gemma**다.

| 신호 | AUROC [95% CI] | TPR [95% CI] | FPR [95% CI] | TP/FPQ | FP/NFP |
|---|---|---|---|---:|---:|
| TF-IDF text | .756 [.639,.856] | .154 [.093,.214] | .033 [.000,.106] | 18/117 | 1/30 |
| hidden logistic | .638 [.514,.742] | .060 [.023,.106] | .033 [.000,.109] | 7/117 | 1/30 |
| 내부 DiM (`mean`) | .731 [.625,.832] | .256 [.168,.335] | .067 [.000,.173] | 30/117 | 2/30 |

**발견.** DiM은 이 운영점에서 더 많은 FPQ를 잡지만 정상 오탐도 1개 더 있다. AUROC 최고는 text이고 hidden 우위는 확인되지 않았다. CI가 겹친다는 것만으로 동등성을 증명하지 않는다. CI는 적합된 모델을 고정한 source-group bootstrap이며 학습 불확실성 전체를 반영하지 않는다.

**다음 판단.** 이 표는 질문 분류만 다룬다. 답변의 교정 정확성·과교정 감소·selective steering은 아직 보여주지 않는다. 내부 성능이 낮다는 이유를 문체 교란으로 확정하지 않고, 필요하면 위치·최소 쌍·전이 통제로 검증한다. 현 결과를 보고 동일 dev를 끝없이 튜닝하지 않는다.

## 9. 출력 512 제한: baseline 자체를 공정하게 읽기 위해 중지·전환했다

사용자 status에서 Plain 732개 중 362개(49.5%), 당시 CoT 58개 중 40개(69.0%)가 final cap에 도달했다. CoT는 일부 완료 표본이므로 두 비율을 전체 방법 비교로 쓰지 않는다.

**왜 진단했나.** 답변 중간이 잘리면 correction이나 최종 결론이 나오기 전에 평가할 수 있다. 그렇다고 무조건 길게 하면 정확해지는 것은 아니므로, fit의 score-blind 8 FPQ+4 NFP에서 길이만 바꾸는 비교를 만들었다. CoT reasoning은 두 final 조건에서 같은 것을 사용했다.

| 방법 | final cap | 완료 | length stop | EOS stop | review length stop |
|---|---:|---:|---:|---:|---:|
| Plain | 512 | 12/12 | 7 | 5 | 0 |
| Plain | 1024 | 12/12 | 0 | 12 | 0 |
| Zero-shot CoT | 512 | 12/12 | 8 | 4 | 0 |
| Zero-shot CoT | 1024 | 12/12 | 0 | 12 | 0 |

Plain 7개, CoT 8개 답변이 바뀌었고, 모두 512 length stop→1024 EOS였다. decoded-text prefix divergence 0, reasoning mismatch 0. 원 Plain replay도 12/12 동일했다. exact token-ID 일치 검사나 정확도 개선 검사는 아니다.

**변경과 보존.** 기존 512 전체 생성 체인은 사용자 Ctrl-C로 중지했다. `prepare_final1024.py`로 별도 suite를 만들고 final cap=1024를 고정했다. 원 512 답변은 보존하며 1024 결과로 재명명하지 않는다. 동일 조건의 reasoning·추출·질문 표상·가용 gate 결과만 검증해 재사용한다. final은 새로 생성하고 judge는 별도다. [절차·원인·명령](reviews/final_budget_check_protocol.md).

Gemma Quick45에서 바꾼 것은 **review 128→1024**, 여기서 바꾼 것은 **Qwen final 512→1024**다. 두 길이 실험을 같은 것으로 쓰지 않는다.

### 마지막으로 받은 진행 로그

`[extract_verify] 319/732: complete` — 사용자 전달 시점의 상태이며 현재 시각의 상태 조회가 아니다. 해당 방법 43.6% 완료, 413개 남음. 기존 순서에서 앞 3방법이 모두 끝났고 뒤에 premise_review 732개가 남았다는 조건하에 남은 생성 문항-방법 작업은 1,145개, 전체 5×732 중 약 68.7% 완료다. 방법별 중간 생성 횟수가 달라 시간 68.7% 완료라는 뜻은 아니다. 이 로그 하나에는 폴더·토큰 설정이 없으므로 실제 1024 적용 여부는 run metadata로 최종 확인해야 한다.

## 10. 실행 중단의 이유를 혼동하지 않는다

| 사건 | 종류 | 연구적으로 의미하는 것 |
|---|---|---|
| Codex ChatGPT 계정에서 gpt-5 미지원 | backend 설정 | 연구 방법 실패 아님. 지원 모델로 변경 |

| generation/score provenance 불일치 | 캐시·출처 관리 | 원 답변·점수 검증 후 제한된 repair, 검사 우회 금지 |

## 11. 다음 실험과 병렬 실행 원칙

현재 baseline은 유지한다. 사용자 결정에 따라 **다음 독립 GPU 실험부터 물리 GPU 0·1 병렬을 기본**으로 한다. 이 문서 변경은 실행 중 코드·프로세스를 바꾸거나 새 작업을 시작하지 않는다.

| 자원 | 병행 가능한 일 | 선행 조건 |
|---|---|---|
| GPU 0 | 현재 baseline 생성 | 현재 run 유지 |
| GPU 1 | 준비된 fit 대조쌍 추출·고정된 후보 생성 | 해당 GPU 여유·모델 한 장 적재·자료 준비 |
| CPU | 저장 표상의 probe/DiM, 보고서·출처 검사 | feature 완료 |
| Terra | fit 답변의 필요한 판정 | 고정 프로토콜·명시한 신규 호출 예산 |

성공/실패 라벨이 필요한 C는 판정 전에 학습하지 않는다. 쌍둥이 실험은 검증된 쌍 준비가 먼저다. 같은 출력 폴더의 중복 writer를 만들지 않고 작업별 GPU·로그·계획·재개 상태를 분리한다. `CUDA_VISIBLE_DEVICES=0,1`만 설정한다고 독립 실험 둘이 자동 분배되지는 않는다. 현재 wrapper의 generate/extract 병렬과 이후 방법별 작업 분배는 별개다.

다음 우선순위는 (1) baseline의 공통 프로토콜 결과와 길이 확인, (2) fit 안의 정확 교정/전제 수용/틀린 반박/정상 과교정 재료 확인, (3) 그 결과로 정한 후보 하나와 독립적인 소규모 진단의 병행이다. 후보별 의존성·수식·비교는 [27](27_method_candidates_and_tests.md).

## 12. 지금 주장할 수 없는 것과 논문 표의 위치

- 내부 probe가 텍스트·CoT보다 낫다는 결론, 선택적 C steering의 유효성, 일반 의료 QA 보존은 아직 없다.
- 정확 교정과 일반 의료적 품질은 다르며 NFP pass는 QA ACC가 아니다. 원 PCR은 정의상 정확 교정을 요구한다. “반박만 하면 +1”은 원 정의가 아니라 잘못된 요약이다.
- 참 전제 쌍둥이 전체가 준비·검증됐다는 확인은 없다. 새 TPQ 제작은 자동으로 확정하지 않는다.
- 실패한 작은 실험만으로 원인이 문체/지식 부재/특정 회로라고 결론 내리지 않는다. 소표본 결과는 효과가 없다는 증명도 아니다.
- 분석 논문/방법 논문의 채택 가능성이나 venue 등급은 현재 수치만으로 보장하지 않는다.

장기 표 역할은 **Table 1 질문 판별, Table 2 최종 교정·정상 보존·일반 의료 QA, Table 3 CREPE 일반화/전이 후보**다. 같은 gate·같은 개입량의 통제는 구성요소 분석으로 둔다. CREPE에서 재학습한 성능과 의료에서 학습한 설정을 고정해 옮긴 전이는 구분하며 방향은 실행 전에 정한다. 과거의 Well RAG 사실 확인 Table 3안은 선행 참고·별도 진단 후보로 남긴다. 현재 코드가 장기 표의 모든 행·열을 실행한 것은 아니다.
