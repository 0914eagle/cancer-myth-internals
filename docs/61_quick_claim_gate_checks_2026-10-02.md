# 빠른 검증: 저장 판정 규칙 재집계와 주장 범위 수정 파일럿

2026-10-02. **실제 의료 답변 생성이 아니라 Luna의 별도 gate 과제를 점검한다.** 기존 721문항의 규칙 재집계는 완료했고, 새로운 80문항 범위 수정 파일럿은 실행 기록에 따라 아래 상태를 갱신한다. 학습·GPU·Well 채점은 사용하지 않는다.

## 1. 새 호출 없이 완료한 것: 기존 판정 규칙 비교

55번의 고정 후보 4조건에서 모두 유효한 721문항(FPQ575/NFP146)의 진위·질문 관계 표시를 재사용했다. 과거 Yes/No의 내부 사고를 복원하거나 진위·관계 표시를 정답으로 인정하는 것이 아니다.

| control 출력에서 적용한 규칙 | FPQ 탐지 /575 | NFP 오탐 /146 |
|---|---:|---:|
| 모델의 원래 최종 판정 | 87 (15.1%) | 8 (5.5%) |
| false 후보가 하나라도 있으면 양성 | 127 (22.1%) | 12 (8.2%) |
| false이며 질문의 전제로 표시된 후보가 있으면 양성 | 73 (12.7%) | 5 (3.4%) |
| false 또는 판단 불가이며 질문의 전제로 표시된 후보가 있으면 양성 | 164 (28.5%) | 26 (17.8%) |

**관계 조건을 고정하고 판단 불가를 양성에 추가하면 FPQ 탐지는 12.7→28.5%, NFP 오탐은 3.4→17.8%로 함께 증가한다.** 질문과의 관계를 무시하고 false만 세어도 둘 다 증가한다. 이것은 가능한 모든 불확실성 처리 방법이 실패한다는 결과가 아니며 같은 오탐률·독립 평가에서의 개선 여부를 검증한 것도 아니다. 임의 규칙에서 Yes가 늘었다는 이유만으로 원인을 해결했다고 부르지 않는다.

## 2. 새로 실행하는 것: 같은 검증기에 원 목록과 범위 수정 목록 제공

기존 주장 목록에 원문보다 강해진 표현이 있다면 이를 고치는 것이 실제로 도움이 되는지 작은 규모로 시험한다. 모든 개인 상황을 보호하라는 지시를 다시 최종 판정기에 붙이는 실험과는 다르다. **바뀌는 입력은 후보 주장 문장이고, 두 조건의 최종 판정 지시는 같다.**

| 항목 | 고정한 절차 |
|---|---|
| 모델 | `gpt-5.6-luna`, medium; CLI preflight 확인, 도구 금지 |
| 문항 | 기존 후보가 준비된 723문항에서 라벨별 무작위 40개씩, 총80개. seed 2026100207. 이전 성공·실패 여부로 선정하지 않음 |
| 원 후보 | 기존 Luna 기본 구조화 출력의 주장·원문 인용. 이전 진위·이유·확률·최종 판정 제거 |
| 범위 수정 | 모델에게 질문과 후보만 제공. 원문에 없는 강화·관계 변경만 수정, 실제 인과·유일성·일반화는 보존. 새 의학 지식·주장·정답을 넣지 못하게 지시 |
| 수정 출력 검사 | 후보 개수·순서·ID·인용문 유지 검사. 의미 보존 성공은 자동 검사가 보장하지 않으며 원문 확인 필요 |
| 공통 검증기 | 55번 control과 같은 원 질문+후보 평가 지시 및 개인 상황 보호 지시. 원 목록/수정 목록 모두 동일 |
| 호출 | 문항당 수정1회+원 목록 판정1회+수정 목록 판정1회 = 240회. 8개 동시 처리, 호출당240초 |
| 비교 | 두 판정이 모두 유효한 문항에서 FPQ/NFP별 Yes 변화, 바뀐 주장 수, 주장 불변인데 판정이 바뀐 수 |
| 숨긴 정보 | 라벨·문항ID·주석·과거 점수와 판정·수정 이유를 최종 검증기에 전달하지 않음. 후보 대응용 c0 등은 유지 |
| 범위 | 이미 분석해 온 벤치마크의 탐색 파일럿. 새로운 holdout·일반화 성능이나 전체 실패 원인 비율이 아님 |

수정 목록은 오류가 실제로 고쳐진 정답 목록이 아니다. 수정기가 거짓 전제를 오히려 약화하거나 없앨 수도 있다. 바뀐 판정은 원문과 목록을 확인해야 해석할 수 있다. 한 번씩 생성하므로 입력이 바뀌지 않은 문항의 판정 차이도 별도 보고하며, 그 부분집합만으로 전체 무작위성을 완전히 보정하지 않는다.

상태·원문: `results/frontier_cli/luna_scope_repair_pilot_20261002_v1/`의 `plan.json`, `evaluation_questions.json`, `status.json`, `run.log`, 각 문항 `record.json`.

```bash

python3 scripts/run_luna_scope_repair_pilot_20261002.py --analyze-only
```

STOP 파일 또는 인증·할당량·전송 오류가 발생하면 이 실험을 멈추고 원문을 보존한다. 실패 응답을 자동으로 고치거나 다른 모델로 대체하지 않는다. 완료 후 결과와 실패 수를 이 문서에 추가한다.


## 3. 실행 기록

Luna preflight는 요청 모델 `gpt-5.6-luna`로 통과했다. 최초 8개 병렬에서 14호출 완료 후 `Selected model is at capacity` 오류로 해당 실행을 중단했다. 실패·취소된 8기록은 별도 보존하고 완료된 14기록을 재사용해 **같은 모델·같은 프롬프트, 4개 병렬로 한 번 재시도**했다. 이는 형식 답변을 선택적으로 고친 것이 아니라 전송 실패 재시도이며 원 로그를 유지했다.
