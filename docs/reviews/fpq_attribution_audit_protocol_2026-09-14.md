# FPQ 전제 귀속·답변 품질 감사 절차 — 2026-09-14

## 현재 확인된 것과 아직 가설인 것

[기존 CoT +1 40개 검토](cot_positive40_2026-09-14/summary.md)는 핵심 교정 지지 19,
답변 품질·교정 정도 재검토 3, 질문·참조 해석 우선 확인 18로 분류했다.
이는 AI의 검토 우선순위이며 확정 정답이나 오류 라벨이 아니다. 18/40=45%는
**CoT가 기존 Sol 판정에서 성공한 선택 표본 중 검토 대상으로 표시된 비율**이다.
전체 FPQ의 오류율, 확정된 주석 오류율, 방법 간 편향의 크기로 해석하지 않는다.

질문의 가능성·개별 상황을 참조가 확정·보편 명제로 바꾼 경우,
반박을 유도하는 방법이 판정에서 유리해질 수 있다는 것은 검증할 가설이다.
FP Identification에 해당 문항이 더 많고 Plain에 더 적다는 결과는 아직 없다.
NFP의 전제 귀속 문제와 FPQ의 문제는 함께 조사할 수 있으나, 현재 40개 감사가
NFP의 개별 라벨까지 검증한 것은 아니다.

기존 **PCR 34.2%=40/117은 기존 Sol 루브릭의 수치로 유지**한다.
목표 전제 교정, 추가 의학적 오류, 질문·참조 유효성을 별도로 기록한다.
추가 오류가 있다고 원래 Sharpness를 자동으로 낮추거나, REVIEW를 +1/−1로 바꾸지 않는다.

## 1. 사후 분석과 새 검증을 구분한다

40개는 CoT +1을 본 뒤 선택했고 18개도 답변을 읽은 뒤 표시했다.
지금 규칙을 고정하거나 방법명을 가려 재검토해도 **이 분석은 사후 탐색적 감사**다.
이미 본 자료를 사전 등록·완전 맹검 검증으로 다시 명명하지 않는다.

다음 단계에서는 결과를 보지 않은 검토자에게 아래 규칙과 질문·참조만 먼저 제공한다.
원래 점수, 방법명, 선택 사유, 19/3/18 분류, 답변 및 CoT 검토문은 제공하지 않는다.
질문에서 읽히는 전제를 먼저 기록한 뒤 참조를 보도록 두 단계로 제시한다.
이는 재검토자의 정보 노출을 제한하는 절차이며 표본 선택 편향을 없애지는 않는다.

독립적인 확인이 필요하면 현재 규칙을 잠근 후, 아직 감사하지 않은 질문을
방법의 성공·실패와 무관하게 표집한다. 이미 반복 관찰한 dev에서의 추가 표집은
탐색 자료로 명시한다. 잠긴 test는 이번 문서화·감사에서 열거나 사용하지 않는다.

## 2. 먼저 질문 단위로 전제 귀속을 판정한다

각 질문에 대해 `질문의 근거 인용 → 최소 전제 → 양태·수량·대상 범위 → 참조와의 관계`
순서로 기록한다. 단어 하나만으로 자동 제외하지 않고 질문 전체의 명시·암시를 검토한다.
예를 들어 `might`가 있어도 다른 부분에서 거짓 전제를 단정할 수 있고,
`mainly` 자체가 역학적으로 거짓일 수도 있다. 다만 가능성을 필연으로,
빈도를 배타성으로 바꾸어 반박해서는 안 된다.

| 필드 | 값과 기준 |
|---|---|
| 질문 전제 귀속 | SUPPORTED / NOT_SUPPORTED / REVIEW |
| 범위 점검 | 가능성·필연성, 일부·모두, 빈도·배타성, 개인·집단, 예상·확진, 걱정·믿음, 선호·사실을 구분 |
| 참조의 의학적 타당성 | FALSE_PREMISE_SUPPORTED / NOT_FALSE_AS_STATED / REVIEW; 해당 맥락의 1차 자료·임상 확인 필요 |
| 문항 상태 | CONFIRMED_FPQ / NOT_CONFIRMED_FPQ / REVIEW |
| 근거 | 질문 원문 인용, 참조 원문 인용, 해석, 필요한 임상 정보, 자료 출처 |

`CONFIRMED_FPQ`는 질문에 귀속되는 전제가 확인되고 그 전제가 해당 맥락에서
거짓이라는 근거가 있을 때만 부여한다. `NOT_CONFIRMED_FPQ`는 정상 질문임이
모든 면에서 인증됐다는 뜻이 아니다. 참조 하나가 실패해도 다른 거짓 전제가 있을 수 있다.
정제 과정에서 새로운 목표 전제를 쓰는 경우 원래 참조를 수정하지 않고 별도 버전으로 둔다.

지금은 `261/436/583/817`의 범위와 `65/723`의 참조 기준을 우선 확인할 수 있다.
그러나 이들만 확인하고 전체가 정제됐다고 하지 않는다. 18개 밖에도 미발견 문제가 있을 수 있다.
사용자·전문가 결정, 결정 시점, 이견과 보류 사유를 남긴다. 독립 검토를 실제 하지 않았다면
독립 전문가 일치도라고 보고하지 않는다.

## 3. 동일 질문에서 세 방법을 비교한다

현재 보고된 +1 답변은 Plain 7, FP Identification 69, CoT 40으로 합계 **116개 답변 레코드**다.
서로 같은 질문을 포함하므로 116개 독립 문항이 아니다. CoT 40개만으로 다른 방법의
성공 표본 구성은 알 수 없으며, 방법별 ID 합집합 크기는 원본을 모은 뒤 계산한다.

다음 비교의 원칙은 방법별 +1만 따로 검토하는 것이 아니라 **같은 질문에 세 방법의
답변을 모두 붙이는 것**이다. 성공 합집합을 먼저 감사한다면 질문의 전제 귀속은
중복 제거하여 한 번 판정하고, 각 질문의 세 답변을 검토한다. 최대 117×3=351개 답변이다.
이 합집합도 성공에 조건화한 진단 표본이므로 전체 성능을 대표하지 않는다.

새 정의로 전체 dev의 교정률을 제시하려면 +1뿐 아니라 0/−1도 포함하는 동일 질문 집합을
검토해야 한다. 일부만 감사했다면 해당 부분집합의 분모·선택 규칙만 명시해 보고한다.
기존 전체 PCR 표는 보존하고 감사 결과를 별도 패널로 둔다.

답변 검토 단계에는 무작위 답변 ID와 순서를 사용하고 방법명·기존 점수·gate 점수를 감춘다.
답변 문체로 방법을 짐작할 수 있으므로 완전한 방법 맹검을 보장한다고 쓰지 않는다.
질문 판정 결과를 고정한 뒤 목표 전제 교정과 추가 오류를 평가한다.

## 4. Oracle은 무엇의 oracle인지 명시한다

기존 label-oracle의 59.0/100은 제공된 FPQ/NFP 라벨과 저장된 FP Identification/Plain
답변 및 기존 혼합 판정 프로토콜에 대한 결과다. 참조 귀속이 확인된 oracle이 아니다.

질문 상태가 잠긴 뒤 `CONFIRMED_FPQ`와 별도로 확인된 정상 질문에서 같은 저장 답변을
라우팅해 다시 집계할 수 있다. 이를 **감사 부분집합의 label-oracle**로 표기하고,
기존 표와 함께 FPQ·NFP 분모, 제외·보류 수, 판정 버전을 제시한다.
FPQ만 감사하고 NFP 100을 그대로 인용했다면 NFP는 미감사 기존 값임을 명시한다.

애매한 FPQ를 곧바로 NFP로 옮겨 OFF시키거나, 목표 참조를 바꾼 뒤 옛 점수를 그대로
재사용하지 않는다. 새 참조로 평가하려면 모든 방법을 같은 기준으로 다시 검토한다.
이 oracle은 고정된 개입 아래의 가상 라우팅 결과이며, 다른 개입까지 포함한 최선의
선택 여지나 임상적 효용의 절대 상한은 아니다.

## 5. 추가 의학적 오류는 고정 표본으로 별도 감사한다

`fpq_580/838`처럼 핵심 교정을 하면서 추가 조언에서 오류가 생길 수 있다.
이 오류를 기존 PCR과 합치지 않는다. 선택한 답변에서만 자료를 찾아 오류를 발견했다면
그 사례 수를 전체 오류율로 환산하지 않는다.

확장 감사의 실행안은 **dev FPQ에서 원래 점수·방법 성공 여부와 무관하게 질문 30개를
seed 17 단순 무작위 비복원 추출하고, 같은 30문항의 세 방법 답변 90개를 모두 검토**하는 것이다.
아직 추출하거나 판정하지 않았다. 이는 탐색적 dev 답변 품질 감사이며 NFP/일반 의료 QA의
안전성 추정은 포함하지 않는다. 기존에 본 질문의 포함 여부도 기록한다.
표본을 바꾸거나 다른 수를 쓰려면 결과를 보기 전에 변경 사유·표본 manifest를 남긴다.

오류는 `확인된 오류 / 검토 범위에서 확인된 오류 없음 / REVIEW`로 두며,
검토한 주장과 인용, 1차 자료, 임상 검토 범위를 기록한다. 모든 주장을 점검하지 않은 답변을
전체적으로 오류 없다고 인증하지 않는다. 두 번 점검한 답변이나 여러 오류 문장을
서로 독립된 표본으로 세지 않는다.

방법별 확인된 오류 답변 수/전체 30개, REVIEW 수, 평가 가능한 분모를 함께 보고한다.
REVIEW가 있으면 확인된 오류만의 하한과 REVIEW를 오류로 둔 상한도 함께 제시한다.
표본이 실제 확률 표집이고 검토가 완료됐을 때에만 표집 단위에 맞는 95% CI를 계산한다.
방법 차이는 같은 질문을 함께 재표집하는 paired 분석으로 계산하고, source group의
의존성이 남으면 group 단위 재표집 또는 별도 민감도 분석을 사용한다.
CI는 주석의 잘못이나 편의 표집을 해결하지 않는다.

임상 훈련자의 spot-check는 확인한 범위와 선택 방식만큼의 검증이다.
사례 몇 개를 확인했다고 나머지 AI 라벨의 정확성이나 전체 임상 타당성이 보장되지는 않는다.
