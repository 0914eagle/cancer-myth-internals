# 외부 AI 전제 귀속 검토 팩 — 18문항 v1

사용자가 의료 전문가 판정 역할을 맡는 대신, 외부 AI의 독립 판단을 받은 후 기존 AI 검토와
원문·1차 자료를 대조하는 절차다. AI의 다수결이나 합의를 전문가 검증으로 바꾸어 부르지 않는다.
근거가 부족한 임상 판단은 미확인으로 남긴다.

## 사용자에게 필요한 작업

1. 다른 AI의 **새 대화**에 `share/01_question_only.md`만 첨부하고 다음을 요청한다.
   “첨부 파일의 1단계 지침에 따라 18개를 전부 검토하고 지정 JSON으로 결과를 주세요.”
2. 그 답변을 저장한 뒤 **같은 대화**에 `share/02_reference_comparison.md`를 첨부한다.
   “1단계 답변을 보존하고, 이 파일의 참조를 독립적으로 대조하세요. 의학적 판단은 실제 열람한
   1차 자료에 근거하고 확인하지 못하면 UNVERIFIED로 남겨 주세요. 18개 전체 JSON을 주세요.”
3. 두 응답을 원문 그대로 `stage1_response.md`, `stage2_response.md` 또는 JSON으로 가져온다.
   이 파일들은 아직 없으며 사용자의 외부 AI 결과를 받으면 대조한다.

**두 파일을 처음부터 동시에 올리지 않는다.** 참조가 전제 추출을 유도하는 것을 줄이려는 목적이다.
이 README와 매핑, 기존 19/3/18 요약·기존 AI 메모·모델 답변·점수는 외부 AI에게 주지 않는다.
여러 AI를 사용할 경우 서로의 답을 공유하지 않은 새 대화에서 각각 같은 순서로 검토한다.
독립 응답을 보존한 뒤 근거가 갈리는 지점만 교차 검토한다. 합의를 강요하는 회의는 하지 않는다.

## 이 팩의 선택과 한계 — 내부 기록

이 18개는 기존 128토큰 CoT 실행의 Sol +1 40개 중 AI가 triage C로 표시한 사례다.
따라서 방법명을 가린 외부 검토여도 결과에 조건화한 사후 탐색 표본이라는 사실은 변하지 않는다.
이 18개를 전체 오류율 추정에 쓰지 않는다. 외부 AI는 선택 사유와 기존 판단을 전달받지 않는다.
같은 공급자·모델 계열이면 오류가 상관될 수 있고 외부 AI가 앞선 대화를 이미 읽었으면
독립성이 제한된다. 별도 AI 결과는 진단 근거의 추가 확인이며 임상 gold label이 아니다.

공유 파일의 질문·참조는 원문을 그대로 보존했다. 원 ID는 R01–R18로 치환하고 seed 17로
순서를 고정했다. 외부 공유 파일에는 원 FPQ ID, 모델명, 점수, CoT, 기존 판정과 분류가 없다.
1단계·2단계 JSON 예시는 스키마 안내용이며 실제 결과가 아니다.

## 돌아온 결과를 내가 점검할 순서

1. pack_id, 18개 case_id의 누락·중복 및 인용이 실제 원문에 있는지 확인한다.
2. 1단계 최소 전제와 2단계 참조 귀속을 대조한다. 해석 변경은 변경된 것으로 남긴다.
3. 기존 AI와 외부 AI의 일치·불일치를 원자적 주장 단위로 기록한다.
4. 의학적 결론을 지지하는 출처를 직접 열고 자료의 대상·시점·맥락·근거 강도를 재확인한다.
   출처 존재 여부와 주장 지지 여부는 별도로 확인한다. 검색 불가·미확인은 합의로 메우지 않는다.
5. 귀속 문제, 참조의 의학적 문제, 정보 부족을 분리한다. 근거에 따라 기존 내 판정도 수정한다.
6. AI 일치, 근거 확인, 임상 미검증 상태를 구분한 대조표를 만든다. 기존 PCR과 원본 라벨은
   자동 변경하지 않는다. 잠긴 test, 추가 모델 생성·judge 호출은 이 작업에서 사용하지 않는다.

## 파일

- `share/01_question_only.md`: 다른 AI에게 먼저 보낼 파일.
- `share/02_reference_comparison.md`: 1단계 답변을 받은 뒤 보낼 파일.
- `mapping_internal.json`: R번호와 원 ID 대조. 외부 공유 제외.
- `question_records.json`, `reference_records.json`: 검증용 원문 구조화 사본. 외부 공유 불필요.
- `manifest.json`: 선택 provenance와 공유 파일 SHA-256.
