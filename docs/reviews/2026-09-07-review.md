2026-09-07. 수정 문서 브랜치 `11ae31c540726eea227ce6eb7a53acab5cdc6322`와 구현·확장 문서 브랜치 `1abfd0f27a2fdd03d36357001ee8858aac948ea1`를 함께 검토했다. 두 브랜치는 분기된 상태이며 새 문서 브랜치는 기존 구현 브랜치의 11개 커밋을 포함하지 않는다. 아래 코드 지적은 `1abfd0f`, 새 AUROC/가설 지적은 `11ae31c`에 적용된다.

문서 전체 맥락과 핵심 데이터→판정→활성값→probe→steering 경로를 검토했다. Well-Actually, Cancer-Myth, Two Axes, CAST 원문 관련 절을 대조하고, SDT 수치를 재계산하고, 세 가지 작은 CPU 재현 검사를 실행했다. 전체 pytest, GPU 추론, 원격 서버 상태, 모든 참고문헌을 검증한 리뷰는 아니다. 원본 파일은 수정하지 않았다.

## 총평

높은 false-class 적중률만으로 H1을 기각하지 않도록 수정한 방향은 타당하다. 그러나 새 기준선은 모형에 의존한 잠재 AUROC 추정치이며, 그 값과 probe AUROC의 대소만으로 지식 유무나 H3를 판정할 수 없다. 현재 구현에는 C 추출을 막는 라벨 유실과 성능을 부풀릴 수 있는 평가 경로 문제가 있다. 연구의 타당한 중심은 **배경 전제의 교정을, 정상 질문의 추가 오교정 위험을 제한하면서 개선할 수 있는가**이다. '모델은 안다'나 '조건과 행동 분리가 최초'를 먼저 확정할 필요는 없다.

P1은 본 실험/핵심 주장 전에 수정할 문제, P2는 해석·재현성·실험 설계를 보강할 문제를 뜻한다.

## 1. [P1] 응답 E 행에서 PCR 라벨이 사라져 C 방향 추출이 중단된다

위치: `src/rows.py:388`, `scripts/make_response_rows.py:57`, `scripts/run_e1_model.sh:89`, `scripts/run_direction_c.py:105`.

make_response_rows는 question에 pcr을 붙인 뒤 response_rows를 호출하지만, response_rows가 복사하는 PASSTHROUGH에 pcr/nfp_score/judge_parsed가 없다. 따라서 E 추출 manifest에도 라벨이 없다. wrapper는 라벨을 ACT_AD에만 병합하고 ACT_E에는 병합하지 않는다. run_direction_c의 `pcr in (1,-1)` 필터에서 E 행이 전부 빠져 각 층을 건너뛰고, 최종적으로 `no layers produced a C direction`으로 종료한다.

실제 함수 재현: 입력 `pcr=1, judge_parsed=True` → 출력 E 행에 두 키 모두 없음. GPU가 없어도 확인되는 결정적 연결 오류다.

조치: E 행 작성 후 라벨을 다시 붙이거나 E manifest에도 병합. 수천 건 GPU 실행 전에 question→E row→manifest→C 입력까지 라벨과 유효 클래스 수가 보존되는 통합 검사 필요.

## 2. [P1] E2 기본 평가셋이 A/C 학습 문항과 겹친다

위치: `scripts/run_direction_c.py:118`, `:143`, `scripts/run_e2_steer_125.sh:45`, `scripts/run_steer.py:80`.

C 방향과 저장용 A gate는 전달된 전체 E1 데이터에 fit한다. 기본 E2 wrapper는 같은 questions.jsonl에서 FPQ/NFP 부분집합을 뽑는다. 별도 split 필터나 학습 id 제외가 없어, 기본 경로의 평가 문항은 학습에 사용된 문항이다. 고차원 활성값에 학습한 gate가 정상 질문을 기억하면 NFP 보존과 PCR 개선이 과대평가될 수 있다. E1에서 일부 readout에 수행한 5-fold CV가 이 문제를 해결하지 않는다.

또한 `pcr_auroc_D_via_cE`는 전체 문항 E로 학습한 방향을 같은 문항 D에서 평가한다. 이것도 out-of-fold 수치가 아니다. sweep에서 최대 AUROC 층을 고르고 같은 OOF 예측을 bootstrap한 CI는 층 선택의 낙관성을 반영하지 않는다(`run_probe_sweep.py:118`).

조치: 질문/동일 myth/의역 그룹 기준으로 분리한 train, validation, 최종 test를 먼저 고정. A/C는 train, 층·강도·threshold는 validation, 최종 비교는 test만 사용. 데이터가 작으면 nested grouped cross-fitting으로 방향·gate·선택 절차 전체를 fold 안에서 재학습한다. NFP와 TPQ의 같은 질문은 항상 같은 그룹이다.

## 3. [P1] 파싱 실패가 성공 점수로 집계되고 C 학습 라벨에도 들어간다

위치: `src/judge_prompts.py:14`, `:88`, `scripts/summarize_judge.py:23`, `scripts/make_response_rows.py:41`.

정규식은 `{` 직후 개행을 요구한다. 정상 한 줄 JSON `{"Reason":"failed to correct","Sharpness":-1}`을 넣으면 parsed=False와 Sharpness=+1을 반환한다. summarize는 실패 플래그를 제외하지 않아 이 행을 PCR 성공으로 집계한다. 실패 개수는 FPQ에서만 별도로 표시하며 NFP/TPQ에는 표시하지 않는다. 후속 라벨 작성도 parsed=False를 제거하지 않는다.

재현 결과: 위 한 줄 JSON 한 건을 집계하면 PCR=100%, PCS=1, unparsed=1이다. 이 +1은 본래 −1이어야 하므로 오차 방향도 명확하다.

조치: JSON 형식에 강건한 파서와 점수 범위 검증, 실패 재시도/미판정 처리. 유효 판정만 학습에 사용하고 미판정률을 모든 집합에서 보고한다. 원본 프로토콜 호환용 fallback을 보존하더라도 별도 지표로 분리해야 한다.

## 4. [P1] GPT-4o로 전환해도 Codex 판정 파일을 그대로 재사용한다

위치: `scripts/run_e1_model.sh:74`, `scripts/run_e2_steer_125.sh:49`, `scripts/run_judge.py:104`.

문서는 최종 표를 GPT-4o로 재채점하고 `_judge_gpt4o.jsonl`로 구분한다고 하지만 wrapper는 backend와 무관하게 같은 `_judge.jsonl` 경로를 쓴다. run_judge는 완료 여부를 id만으로 판단한다. Codex 채점 후 같은 wrapper를 `JUDGE_BACKEND=openai`로 재실행하면 완료된 행은 건너뛴다. 부분 파일이면 두 판정기가 섞일 수 있다. summary는 혼합 판정기를 거부하거나 출처를 표시하지 않는다.

조치: backend/model/temperature/rubric/응답 해시를 run identity에 포함하고 저장 경로를 구분. 기존 파일과 실행 설정이 다르면 resume를 중단. 최종 집계 시 판정기 일관성 확인.

## 5. [P1] TPQ의 참 전제를 '언급하면 감점할 환각'으로 전달한다

위치: `scripts/run_judge.py:45`, `src/judge_prompts.py:80`.

TPQ는 true premise_text를 NFP 판정기의 non_assumption 자리에 넣는다. 생성된 지시문은 그 참 전제를 '답변에서 언급하면 −1'로 지정한다. 따라서 참 전제를 올바르게 인정한 답변도 감점 대상으로 제시된다. 이는 TPQ 보존이 의미하는 '정당한 전제를 잘못 부정하지 않음'과 다르다.

실제 prompt 재현: `The patient has a diagnosis.`라는 참 전제를 그대로 인정한 응답에 대해 그 문장을 'should NOT be mentioned'로 지정한다. 실제 판정기가 항상 이 지시대로 감점한다고 검증한 것은 아니지만, 측정 지시 자체가 잘못되어 있다.

조치: TPQ 전용 '부당하게 부정/교정했는가' rubric을 만들고 올바른 인정/잘못된 부정 대조 예시로 보정한다. 기존 NFP 공식 지표는 원래 hallucination_text로 그대로 유지한다. TPQ 새 지표를 공식 Well-Actually S5와 동일하다고 부르면 안 된다.

## 6. [P1, 연구] CAST를 '조건과 행동이 같은 개념'으로 묘사한 차별화는 원문과 다르다

위치: `docs/08_story_outline.md:95`, `:105`, `:131`; `docs/07_related_work_2026.md` B3.

[CAST 원문 §3–5](https://arxiv.org/html/2409.05907)는 조건 벡터 c와 행동 벡터 v를 명시적으로 구분한다. c는 유해성/주제 등에서, v는 refusal/compliance 응답에서 별도로 추출하고, 조건 판독 층과 행동 개입 층도 다르게 선택할 수 있다. 따라서 '조건과 개입을 분리한 것이 우리만의 구조'라는 주장은 성립하지 않는다. 다른 기법 전부를 재검증한 것은 아니지만 CAST 하나만으로 현재의 포괄적 주장은 반박된다.

조치: CAST를 포함한 조건부 steering의 확장으로 정직하게 위치시킨다. 차별점 후보는 배경화된 의료 전제의 신호 검증, 교정 방향의 통제된 추출, NFP에서의 추가 오교정 제약, 동일 gate 아래 prompt 대 activation의 효과 비교다. 동일 데이터로 학습한 CAST식 조건/교정 벡터 baseline을 포함해야 한다.

## 7. [P1, 연구] 환산 AUROC와 실제 probe AUROC의 비교는 현재 상태로 공정하지 않다

위치: 새 브랜치 `docs/02_followups_and_gap.md:34`, `docs/06_experiment_plan.md:34`.

[Well-Actually Table 1](https://arxiv.org/html/2608.06539v1#S3.T1)은 단일 판정 기준에서의 참/거짓 정확도다. 이 한 운영점만으로 연속 score의 ROC 곡선을 식별할 수 없다. 새 표의 수학 계산은 등분산 정규 SDT 가정 아래 맞지만, 실측 AUROC가 아니다.

| 모델 | 등분산 정규 가정의 잠재 AUC | 이진 출력 자체의 AUC |
|---|---:|---:|
| Qwen2.5-7B | 0.6985 | 0.5575 |
| Llama-3-8B | 0.7862 | 0.5970 |
| Gemma | 0.8256 | 0.6065 |
| Gemini | 0.7669 | 0.6290 |
| Med42 | 0.7917 | 0.6300 |

두 열은 서로 다른 대상이다. 오른쪽은 양성=거짓, 동점 0.5 처리 시 `(TPR+TNR)/2`; 왼쪽은 `d′=Φ⁻¹(TPR)−Φ⁻¹(FPR)`, `AUC=Φ(d′/√2)`다. 이번 리뷰에서 직접 재계산했다. 낮은 이진 AUC가 잠재 판별력의 상한이라는 뜻도 아니다.

또한 원문 Table 1은 gold presupposition 단위 평가이며 FPQ 100/TPQ 116을 사용한다. E1의 질문 단위 585/NFP 150과 분모·입력 정보가 같지 않다. 여러 전제가 있는 질문의 집계 규칙까지 맞춰야 한다.

조치: 같은 모델/같은 held-out 질문에 직접 elicitation의 연속 score(log-odds 등)를 수집해 실제 ROC를 계산하고, 출력 기반 readout도 동일 학습 분할에서 calibration한다. gold 전제를 제공하는 oracle baseline과 모델이 스스로 추출하는 end-to-end baseline을 구분한다. SDT 환산표는 가정에 따른 보조 분석으로만 둔다. Two Axes도 [§3의 대칭 readout](https://arxiv.org/html/2607.08456v1)에서 학습된 probe와 학습되지 않은 scalar의 비대칭 비교를 피한다.

## 8. [P1, 연구] probe와 언어 판정의 성능 차이만으로 H1/H3를 판정할 수 없다

위치: 새 브랜치 `docs/03_hypothesis_map.md:30`, `docs/06_experiment_plan.md:62`.

probe > verbal이면 '그 readout으로 라벨 정보에 더 잘 접근한다'는 근거이지 곧바로 '알면서 따른다'는 증명은 아니다. probe ≈ verbal이면 '시험한 readout의 추가 이득을 검출하지 못했다'는 결과이며 지식 부재의 증명도 아니다. 제한된 표본, 선형 probe의 표현력, 토큰/층 선택, 통계적 불확실성으로도 같은 결과가 나온다. A 라벨이 FPQ/NFP 출처와 완전히 연동되므로 문체·암종·생성 모델 shortcut도 가능하다. C는 다른 질문의 PCR+1/−1 평균 차라 태도 외 주제·난도·답변 어휘 차이를 흡수할 수 있다.

조치: 문서의 자동 '접는다/H1 부활'을 readout 수준의 결과로 완화. 텍스트-only/BoW, 생성 출처/암종 holdout, 동일 명제의 참·거짓/배경·단언 대조쌍, 같은 질문의 교정/비교정 응답 대조, A/C 상호 개입 등으로 의미와 인과성을 분리 검증한다. 2×2 셀은 초기에는 측정된 score 조합으로 부르고 H2/H3 확정 라벨로 사용하지 않는다.

## 9. [P2] NFP 보존은 자동 보장이 아니며 전체 AUROC는 목표와 다르다

위치: `docs/08_story_outline.md:100`, 새 브랜치 README, `scripts/run_e2_steer_125.sh:18`, `scripts/run_steer.py:124`.

현재 A gate는 오탐할 수 있고 threshold 기본값 0은 NFP 오탐 예산에 맞춘 값이 아니다. 설계의 `A=거짓 AND C=따라감` 중 C 조건도 구현되어 있지 않다. AUROC가 같아도 낮은 FPR 구간의 TPR은 다를 수 있어, 전체 AUROC 우열만으로 실제 gate 유용성을 판정해서는 안 된다.

조치: A-only와 A∧C를 별도 ablation으로 명시. validation에서 τ/α를 선택하고 test에서 TPR@고정 FPR, gate 발화율, PCR/PCS, NFP의 paired harm/rescue와 신뢰구간을 보고한다. NFP 비열등성 허용폭을 사전에 정한다. 정상 문항 150개에서 추가 오류가 0건이어도, 독립 이항 가정의 한쪽 95% 상한은 약 1.98%다. 150개를 학습·튜닝·평가로 나누면 정밀도는 더 나빠진다.

## 10. [P2] NFP와 자연 분포에 관한 상·하한 및 무손실 논리가 과도하다

위치: 새 브랜치 `docs/02_followups_and_gap.md:46`, `:61`; `docs/08_story_outline.md:137`.

한 LLM이 헛짚은 문항으로 구성했다고 모든 대상 모델의 자연 분포 FPR 상한이나 AUC 하한이 보장되지는 않는다. '어려운 통제군'이라는 설계 동기와 확률적 상·하한은 구분해야 한다. 또 FPQ 비율 13%일 때 TPQ를 1점이라도 잃으면 반드시 진다는 주장도 틀리다. 같은 점수 척도에서 `ΔU=0.13ΔF+0.87ΔT`이므로 FPQ +10점, TPQ −1점이면 총점 +0.43점이다. 원문은 평가한 방법들의 결과이지 모든 미래 방법에 대한 불가능성 정리가 아니다.

조치: NFP 보존은 독립적인 연구 제약으로 정당화. WildChat 100문항에서 추정한 13%를 암 환자 질문의 유병률로 단정하지 말고 여러 비율에서 민감도 분석한다. 공식 PCR/NFP와 원문의 1–5 가중 점수도 구분한다.

## 11. [P2] 판정기 보정에서 얻은 결론을 steering 조건으로 일반화하고 있다

위치: `docs/experiments/01-e1-prediagnostic.md:61`.

3개 답변 모델의 순위가 유지됐다는 사실은 Plain/unconditional/gated 또는 여러 α의 순위가 유지된다는 증거가 아니다. 특히 C를 Codex 판정으로 학습하면 최종 교정 성능보다 Codex가 선호하는 문체 방향을 학습할 수 있다. Cancer-Myth의 GPT-4o–인간 PCR 100% 일치는 [원문 Appendix C.1.1](https://arxiv.org/html/2504.11373v3#A3.SS1.SSS1)의 76개 선별 사례에서 얻은 결과이며 모든 답변에 대한 보장이 아니다.

조치: 실제 steering 출력의 조건별 층화 표본에서 두 judge와 사람의 일치/순위/오류 유형을 재확인한다. 최종 test 전 별도 validation에서 수행하고, 판정기 정확도를 무조건적인 사실로 쓰지 않는다.

## 12. [P2] 재시작할 때 같은 α 조건의 실제 개입 크기가 바뀔 수 있다

위치: `scripts/run_steer.py:89`, `:115`.

완료 행을 제외한 뒤 남은 첫 batch의 residual norm으로 scale을 재계산한다. 중단 후 resume하면 초기 batch가 달라져 같은 α·같은 출력 파일에 서로 다른 alpha_abs의 결과가 이어 붙는다. 행별 alpha_abs는 기록되지만 집계는 이를 구분하지 않는다.

조치: train/validation의 고정 calibration subset에서 scale을 계산해 run metadata로 저장하고 재시작 때 재사용. 큰 기본 α=2/4/8은 residual norm의 배수이므로 작은 강도까지 포함한 안정성 점검도 필요하다.

## 우선순위와 최소 실험

1. 문서 수정분을 구현 브랜치의 최신 문서에 의미상 통합하고, CAST 설명·SDT 표·H1/H3 해석을 먼저 바로잡는다.
2. E 라벨 전달, parser/미판정 처리, judge identity, TPQ rubric을 수정한 뒤 CPU 재현 검사를 통합 검사로 만든다.
3. 질문 그룹 split과 학습/선택/평가 provenance를 고정한다. 이미 만든 독립적인 hidden-state 캐시는 분할 후 재사용할 수 있다.
4. 한 모델에서 output score/probe/텍스트-only baseline을 동일 test에 비교하고 특히 낮은 FPR 구간을 본다.
5. 같은 gate를 공유하는 FP 검사 프롬프트 대 C steering, 무조건 C, 무작위 gate, CAST식 조건/행동 baseline을 비교한다. oracle gate는 실제 배포 방법이 아니라 개입 자체의 잠재력을 진단하는 상한으로만 사용한다.
6. 신뢰할 만한 조건부 교정 효과가 확인된 뒤 AO/NLA 해석과 다중 모델 확장에 투자한다. 해석 실험을 통해 신호가 진위·태도라는 주장을 별도로 검증한다.
