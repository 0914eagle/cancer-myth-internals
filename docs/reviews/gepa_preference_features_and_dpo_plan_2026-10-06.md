# 10월 6일 미팅 이후: 선호 특징을 이용한 GEPA와 DPO 실험 계획

> **표 확장 업데이트 (2026-10-06):** 실제 논문용 표는 [paper_tables_2026-10-06/README.md](paper_tables_2026-10-06/README.md)에 저장했다. 본표에 기존 모델군(Qwen2.5, GPT-6 Luna, Gemma 4, Qwen3.8 OFF/ON)을 넣고 MMLU·GSM8K를 일반 능력 보존 평가로 추가했다. SFT·DPO·NLA/AO와 기존 Gate/CoT 기준선은 추가 표에 포함한다. 아래 최초 2모델 표보다 이 렌더링 버전이 최신이다. 새 실험 결과는 아직 없다.

작성일: 2026-10-06. **방법 설계 및 평가표 초안이며, 새 실험 결과 보고가 아니다.** 기존 원인 분석과 실행 기록은 수정하지 않는다. 미팅 메모의 JEPA는 문맥상 GEPA로 해석했다.

## 1. 지금 추진할 연구

**좋은 교정과 불필요한 반박을 구별하는 특징을 답변 쌍에서 찾아, GEPA의 피드백과 선호 학습에 활용한다. 필요한 교정을 높이면서 정상 질문과 일반 QA 성능을 보존하는지 평가한다.**

원인을 완전히 입증해야만 방법을 시작하는 계획은 아니다. 방법의 가설은 “문항별 점수·자유 서술 피드백에 더해, 여러 답변 쌍에서 검증한 행동 특징을 제공하면 최적화가 더 잘 일반화될 수 있다”이다. 효과와 차별성은 비교 실험으로 확인해야 한다.

“GEPA는 소수의 규칙만 찾아서 일반화하지 못한다”는 아직 입증하지 않았다. 규칙 수가 적다고 나쁜 것도, 프롬프트가 길다고 반드시 과적합하는 것도 아니다. WIMHF도 적은 수의 해석 가능한 특징을 찾는다. **규칙 개수보다 피드백이 무엇을 구별하는지, 그 구별이 새 문항에서도 유효한지가 중심이다.**

## 2. 가져올 방법과 결합할 때의 경계

| 방법 | 원래 하는 일 | 이번 연구에서의 역할 |
|---|---|---|
| What's In My Human Feedback? Learning Interpretable Descriptions of Preference Data (WIMHF) | 두 답변의 임베딩 차이에 SAE를 학습하고, 특징을 언어로 해석하여 선호 라벨과의 관계를 분석 | 답변 쌍에서 반복되는 차이를 찾아 피드백 기준 후보로 사용 |
| Natural Language Autoencoders (NLA) | 대상 모델의 활성값을 자연어로 설명하고 활성값 재구성으로 학습 | 공개 모델에서 답변 텍스트만으로 얻기 어려운 추가 설명이 있는지 확인 |
| Activation Oracles: Training and Evaluating LLMs as General-Purpose Activation Explainers (AO) | 대상 모델의 활성값을 입력받아 이에 관한 질문에 자연어로 답함 | NLA와 별도의 내부 정보 활용 후보 |
| GEPA | 실행 결과와 피드백을 이용해 프롬프트 후보를 수정·선택 | 검증한 특징 설명을 반성 과정에 제공하고 답변 프롬프트 최적화 |

근거: [WIMHF 논문](https://arxiv.org/html/2510.26202), [NLA 공식 설명](https://www.anthropic.com/research/natural-language-autoencoders), [AO 논문](https://arxiv.org/abs/2512.15674).

**WIMHF의 SAE는 답변 생성 모델의 내부를 직접 읽는 SAE가 아니다.** 따라서 Luna의 답변 텍스트도 외부 임베딩 모델로 분석할 수 있다. 반면 NLA·AO는 대상 모델과 호환되는 내부 활성값 및 설명기가 필요하다. WIMHF의 임베딩 차이 벡터를 NLA·AO에 그대로 넣는 연결은 성립하지 않는다.

WIMHF 원 논문은 답변만 임베딩했다. 공식 코드의 2026년 4월 업데이트는 질문을 포함한 로컬 임베딩 모델 사용을 권하지만, 그 벡터로 전체 후속 평가를 다시 수행하지는 않았다고 명시한다. 이번에는 문맥 의존적인 선호를 다루므로 질문을 포함하는 변형을 우선 후보로 삼되 **원 논문 완전 재현이라고 부르지 않는다.** [공식 구현 및 업데이트](https://github.com/rmovva/wimhf)

### SAE 특징을 실제로 해석하는 절차

WIMHF는 AO를 사용하지 않는다. 한 특징의 값이 큰 답변 쌍 5개를 골라 일반 LLM에 두 답변의 공통적인 차이를 설명하게 한다. 별도 쌍에서도 그 설명이 특징의 활성값과 맞는지 검사한 다음, 실제 선호 라벨과의 관계를 분석한다. **특징에 이름을 붙이는 것과 그 특징을 선호하는지 판단하는 것은 별도 단계**이다. [원문 §3 및 부록 A.3](https://arxiv.org/html/2510.26202#A1.SS3)

AO의 설계에는 대상 LLM 활성 공간의 SAE 특징 벡터를 해석하는 접근도 포함된다. 다만 WIMHF가 외부 문장 임베딩에 학습한 SAE는 그 공간과 다르다. 따라서 “SAE를 AO로 해석할 수 있다”와 “WIMHF SAE를 공개 AO에 그대로 넣을 수 있다”는 다르다. 내부 SAE를 택하면 대상 모델·레이어·SAE·AO의 호환을 먼저 확인해야 한다. [AO §3.1 및 부록 G](https://arxiv.org/html/2512.15674)

추가 한계: WIMHF는 원래 객관적 정답이 있는 질문을 제외하고 주관적 선호를 중심으로 평가했다. 따라서 의료 사실의 정오까지 임베딩 특징으로 구별할 수 있다고 가정하지 않는다. 이번 적용에서는 사실 주석과 별도 평가를 유지한다. [WIMHF §4](https://arxiv.org/html/2510.26202)

## 3. 먼저 실행할 흐름: Response 프롬프트 최적화

1. **분할을 먼저 고정한다.** 같은 원 질문의 여러 답변, 수정 질문, 같은 통념·출처에서 파생한 문항을 같은 그룹에 둔다. 특징 발견용 학습, 후보 선택용 개발, 최종 평가를 분리한다.
2. **학습 질문의 답변 쌍을 모은다.** Plain·GEPA·전제 검토 등의 저장 답변 중 사용 가능한 자료를 연결한다. 현재 노출 이력이 있는 199문항은 개발 자료로 취급한다. 문항이 아니라 답변 조합을 늘린 것을 독립 표본 증가로 세지 않는다.
3. **선호를 검토한다.** 점수 차이만으로 chosen/rejected를 확정하지 않는다. 실제 목표 교정, 원문에 없는 반박, 요청 응답을 확인하고 동점·애매한 쌍은 별도 보관한다. LLM 라벨이면 human feedback이 아니라 AI feedback 기반 적용이라고 명시한다.
4. **WIMHF식 특징을 찾고 설명한다.** 학습 답변 쌍에서 얻은 특징 설명이 별도 개발 쌍에서도 맞는지 확인한다. 길이·문체만 설명하는 특징과 과제 행동을 설명하는 특징을 구분한다.
5. **설명을 피드백 기준 후보로 만든다.** 선호와 상관된 특징이 곧 올바른 의료 기준은 아니다. 질문의 문맥과 주석에 비추어 사용할 특징을 검토한다. 질환별 정답을 적은 규칙 대신 새로운 질문에도 적용할 수 있는 조건부 기준을 남긴다.
6. **GEPA의 반성 입력에 추가한다.** 기존 질문·답변·점수·채점 이유에 “어떤 특징이 어느 답변에서 나타났는지”를 보탠다. 처음에는 답변 프롬프트만 최적화한다. 최종 평가 기준은 바꾸지 않는다.
7. **미사용 평가 자료에서 비교한다.** 원래 GEPA와 같은 모델·후보 평가 예산을 사용한다. 특징 발견 비용까지 별도로 보고한다. 같은 모델에서 최종 조건을 반복 실행한다.

아래는 이해를 돕는 예시이지 SAE로 이미 발견한 특징이 아니다.

> “반박을 많이 한다”는 특징만으로는 FPQ와 NFP를 구별하지 못한다. 대신 “질문의 실제 주장과 관련된 잘못된 추론을 고치고 요청에도 답한다”와 “질문에 없는 더 강한 주장을 만들어 반박한다”를 구별할 수 있는지 본다. 사용자 보고라는 이유만으로 모든 내용을 참으로 취급하는 규칙은 사용하지 않는다.

### NLA·AO는 어디에 추가하나

공개 모델의 같은 질문·답변에 대응하는 활성값에서 설명을 얻고, 답변 쌍 특징과 연결한다. 추출 위치·레이어·시점은 학습/개발 자료로 정하고 시험 자료에서 바꾸지 않는다. 우선 NLA 또는 AO 하나씩 평가한다.

**그 설명이 유용한 피드백인지가 시험 대상이며, 모델이 실패한 진짜 원인이라고 전제하지 않는다.** 텍스트만 본 설명기, 활성값을 가린 설명기, 다른 문항의 활성값을 준 설명기를 대조한다. 이 대조보다 나아야 내부 정보의 추가 가치를 주장할 수 있다.

## 4. Detection과 Response 중 어디에 적용하나

| 적용 위치 | 바꾸는 것 | 처음 확인할 질문 | 우선순위 |
|---|---|---|---|
| Response | 실제 답변 지시의 GEPA 피드백 | 필요한 교정과 정상 질문 보존을 함께 개선하는가 | 주 실험 |
| Detection | Yes/No 판단 또는 주장 판정 지시의 GEPA 피드백 | 같은 오탐 수준에서 탐지가 개선되는가 | 후속 실험 |
| 검증기+답변 전체 | 고정된 파이프라인 안에서 두 지시를 각각 또는 함께 최적화 | 어느 단계의 변경이 최종 답변 개선에 필요한가 | 앞 두 결과 후 |

Detection 적용은 자동으로 따라오지 않는다. 답변 선호에서 얻은 특징이 판정 과제에도 유효한지 따로 검증해야 한다. 추후 파이프라인 비교에서는 `둘 다 고정 / 검증기만 변경 / 답변만 변경 / 둘 다 변경`의 2×2를 사용한다. 서로 다른 추출기·호출 수를 섞어 단계 효과라고 해석하지 않는다.

## 5. Antidote에서 가져올 DPO와 발전시킬 부분

**Antidote: A Unified Framework for Mitigating LVLM Hallucinations in Counterfactual Presupposition and Object Perception**은 이미지 거짓 전제 질문에서 사실 단서를 이용해 교정 답변을 만들고, 원래 환각 답변과 선호 쌍을 구성한다. 과도한 조심성을 완화하기 위해 참 전제 질문도 학습에 포함한다. [논문](https://arxiv.org/html/2504.20468), [공식 코드](https://github.com/Wu0409/Antidote)

텍스트에서는 이미지가 제공하던 사실 기준이 사라진다. 그러므로 “이미지를 빼고 같은 DPO”만으로는 충분한 발전이 아니다. 교정의 근거와 정상 질문 보존의 근거를 어떻게 확보했는지가 추가 설계가 된다.

**제안: 문맥에 따라 선호가 바뀌는 답변 쌍을, 검증한 특징을 이용해 구성·선별한다.**

| 질문 종류 | chosen 후보 | rejected 후보 | 점검할 점 |
|---|---|---|---|
| FPQ | 실제 목표 오류를 교정하면서 요청에 답함 | 오류 수용, 목표 교정 누락 | 단순히 더 강하게 반박해서 선택되지 않았는가 |
| NFP | 원문 의미를 유지하고 요청에 답함 | 질문에 없는 오류를 만들어 반박 | 정상적인 부정 답변·한계 설명을 부당한 반박으로 오인하지 않았는가 |
| 일반 의료 QA | 정답과 관련 설명을 제공 | 사실 오답 또는 불필요한 회피 | 길이·친절함만으로 선호가 결정되지 않았는가 |

최소 대조 질문을 만들 경우 원본 벤치마크와 별도 학습 자료로 기록한다. 주석 검토 없이 참/거짓을 단어 치환만으로 확정하지 않는다. 원본과 수정본은 같은 분할에 둔다.

비교는 같은 공개 모델에서 수행한다.

- 같은 chosen 답변으로 학습한 SFT.
- FPQ·NFP를 함께 쓰는 기본 DPO: Antidote의 균형 학습 발상을 적용한 텍스트 기준선.
- 특징을 이용해 선별한 쌍으로 학습한 DPO: 데이터 수·질문 구성·학습 예산을 맞춘다.
- 필요하면 일반 QA 혼합 여부를 양쪽 DPO 모두에서 비교한다. 특징 선별과 QA 혼합 효과를 한 번에 바꾸지 않는다.

특징 설명을 프롬프트에 사용하는 GEPA와 선호 쌍 선별에 사용하는 DPO를 먼저 각각 검증한다. 둘을 결합한 최종 시스템은 각 요소의 효과가 확인된 후 평가한다. 이 조합의 신규성은 아직 확정하지 않았다.

## 6. 모델 및 데이터 역할

| 모델 | 주 용도 | 내부 설명 | 이번 계획에서의 상태 |
|---|---|---|---|
| GPT-6 Luna | 프론티어 Response, GEPA, 답변 특징의 전이 평가 | 직접 NLA/AO 적용 불가 | 기존 실행기 기반. 새 최적화는 미실행 |
| Gemma-3-12B-it | 공개 모델 Response·NLA·SFT/DPO | 공개 NLA L32 호환 대상 | 로컬 설정 있음. 실제 가중치·메모리·설명기 구동은 별도 확인 |
| Gemma-2-9B-it | AO를 사용할 경우의 별도 공개 모델 후보 | 해당 모델 AO 체크포인트 호환 확인 후 | 보조 트랙. Gemma-3와 점수를 섞지 않음 |
| Qwen2.5-7B-Instruct | 기존 결과 연결 또는 추가 전이 | 공개 NLA L20 호환 대상 | 여력 있을 때 확장 |
| 기존 Gemma 4 12B·Qwen3.8 OFF/ON | 기존 모델군으로 텍스트 루브릭 전이 평가 | 위 NLA와 호환한다고 가정하지 않음 | 주 효과 확인 후 확장 |

NLA 지원 모델·레이어는 [공식 추론 코드](https://github.com/kitft/nla-inference)를 기준으로 하며, AO는 [공식 코드](https://github.com/adamkarvonen/activation_oracles)에서 체크포인트별로 확인한다. **과거 Gemma 4 수치를 Gemma-3-12B 결과 칸에 넣지 않는다.** 공개 모델에서 얻은 자연어 기준을 Luna로 전달하는 것은 가능하지만, 이를 Luna 내부를 분석했다고 표현하지 않는다.

## 8. 해석과 재현 규칙

- FPQ/NFP 문항 수를 반드시 같게 만들 필요는 없다. 학습 배치 구성과 목적함수의 가중치를 별도로 정한다. 기본 비교는 두 집단 평균 점수에 같은 가중치를 주고 집단별 결과를 함께 보고한다.
- 단일 평균 향상만으로 trade-off 개선이라고 부르지 않는다. 두 지표, 문항별 전환, 반복 실행의 신뢰구간, 사전에 정한 NFP/일반 QA 보존 허용폭을 함께 본다. 유의하지 않은 하락이 곧 보존 증명은 아니다.
- 평가 프롬프트와 최종 루브릭은 실험 전에 고정한다. 발견한 루브릭으로 생성기를 튜닝하고 그 루브릭으로만 평가하는 순환을 피한다. 최종 독립 검토 표본은 조건명을 가린다.
- 조건별 실행 3회는 초기 반복 계획이다. 같은 저장 답변 재채점과 새 답변 재생성을 구분한다. 최적화·특징 발견·추론 비용과 호출 수를 각각 기록한다.
- 새 조건을 기존 199문항으로 계속 수정하면 그 문항은 개발 자료다. 남은 Cancer-Myth도 과거 노출 여부를 확인하고 완전히 미사용이라고 단정하지 않는다. 평가 자료가 확보되지 않으면 탐색 결과로만 보고한다.
- NLA/AO 설명 및 WIMHF 선호 특징은 사실 정답이나 인과 증거를 자동 제공하지 않는다. 그 추가 정보가 실제 미사용 평가 성능을 개선하는지가 판단 기준이다.

## 9. 바로 다음 작업

1. **자료 준비:** 기존 답변 원장에서 학습용 후보 쌍을 추출하고 question_id·myth/source 그룹·노출 이력·선호 출처·동점/불확실을 기록한다. 새 모델 대량 생성 전에 사용 가능한 고유 질문 수를 확인한다.
2. **첫 방법 비교:** Luna에서 기존 GEPA / 텍스트 요약 피드백 GEPA / WIMHF식 피드백 GEPA를 같은 조건으로 비교한다. 공식 구현의 로컬 임베딩 경로를 이용할 수 있지만, 환경 설치와 실행은 아직 하지 않았다.
3. **공개 모델 확장:** Gemma-3-12B NLA 호환·메모리를 점검하고 내부 설명의 추가 가치를 시험한다. 같은 학습 쌍으로 SFT·DPO 기준선을 준비한다. AO는 호환 모델에서 별도 비교한다.

> 기존 GEPA의 문항별 피드백에 더해, 선호 답변 쌍에서 반복되는 특징을 찾아 최적화에 활용하는 방향으로 진행하겠습니다. WIMHF식 특징 발견을 먼저 답변 프롬프트 최적화에 연결하고, 공개 모델에서는 NLA 또는 AO로 얻은 내부 설명이 추가로 도움이 되는지 비교하겠습니다. 같은 특징을 활용한 선호 데이터 구성도 기본 SFT·DPO와 비교하겠습니다. Cancer-Myth와 CREPE의 교정·정상 질문 보존을 함께 측정하고, 일반 의료 QA 성능을 유지하는지도 평가하겠습니다.
