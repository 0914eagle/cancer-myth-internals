# Cancer-Myth 732문항: 원본 대조와 필드 의미 정합성 검사 (2026-10-13)

**현재 파일은 가져온 원본과 일치한다. 다만 원본의 `source_myth`가 모든 질문의 정확한 전제를 뜻하지는 않는다.** 따라서 “다운로드/변환 중 내용이 망가졌다”와 “출처 통념·질문·교정 설명이 서로 다른 범위를 다룬다”를 구분해야 한다.

## 1. 범위와 확인 수준

- 원장: `configs/premise_sft/cancer_questions.jsonl`, **FPQ 583 + NFP 149 = 732**.
- 732개 전부 원본 필드 대조, 732개 전부 GPT-6 Sol의 고정 지시문에 의한 의미 관계 분류. 임상적 진위나 FPQ/NFP 정답 라벨 재판정은 수행하지 않았다.
- 자동 분류에서 다른 주장으로 나온 74개 모두에 대해 주 에이전트가 질문·출처 통념을 직접 대조했다. 33개는 다른 판정 대상, 26개는 함의/범위 문제, 15개는 해석을 보류했다. 이는 임상적 정답 라벨 판정이 아니다.
- 별도로 13개 사례(정합적인 대조 사례 포함)는 Codex 주 에이전트가 실제 질문·필드를 직접 대조하여 한국어 검토 기록을 추가했다. 독립적인 사람/임상 전문가 검증이 아니다.
- A6000에서 이전에 표시된 46개 명단은 확보하지 못했다. **이 검사는 그 46개에 대한 재판정/재현이 아니라, 현재 원장 전체에 대한 별도 검사다.**
- 모델·지시문·입력 해시는 `protocol.json`. 배치 32개, 동시 호출 2개, 기존 공통 GPT 4슬롯 공유. 본 검사 때문에 기존 데이터·라벨·점수를 수정하거나 실험을 중단하지 않았다.

## 2. Hugging Face에서 그대로 가져왔는가?

| 대상 | 실제 출처 | 대조 결과 |
|---|---|---|
| FPQ 583개 | Hugging Face `Cancer-Myth/Cancer-Myth`의 로컬 캐시 | 질문, `source_myth`, `presupposition_correction` 모두 일치 |
| NFP 149개 | 원 Cancer-Myth GitHub의 `data/nfp.json` | 질문 모두 일치. Well에 포함된 사본도 원 GitHub 로컬 사본과 전체 JSON 일치 |
| 현재 실행 bundle 724개 | 위 732개에서 few-shot 관련 8개 제외 | 질문 및 FPQ 전제·reference 내용 변경 없음 |

**변환 중 내용이 달라진 문항: 0/732.** 질문의 앞뒤 공백 제거는 허용한 비교다. 새로 원격 최신본을 다운로드한 비교가 아니라, 실제 로딩 코드 및 보관 중인 원본 스냅샷과의 대조다. 경로·해시는 `source_comparison.json`에 보존했다.

배포 원본은 FPQ 585 / NFP 150개다. 우리 732개 원장에서는 채점 예시인 `fpq_1`과, 동일 질문에 FPQ/NFP 라벨이 모두 붙은 `fpq_419`·`nfp_1007`을 이미 제외했다. 현재 724개 실행 자료의 추가 8개 제외와는 다른 단계다.

| 원본 필드 | 우리 쪽 필드 | 실제 의미/주의 |
|---|---|---|
| `question` | `question` | 평가 질문 |
| `source_myth` | `premise_text` → `presuppositions[0]` | 출처 통념. 질문의 정확한 전제와 항상 같지는 않음 |
| `presupposition_correction` | `correction` → `reference_answer` | 질문의 오류 설명/교정 설명 |
| NFP `example_assumption` | 과거 loader의 `hallucination_text`; 검사에서 `nfp_source_note` | 원본 메모. 현재 NFP의 정답 거짓 전제나 교정문으로 사용하지 않음 |

Well의 CancerMyth 준비 코드도 `source_myth`를 `presuppositions`로 옮긴다. 따라서 우리 코드만의 독자적 필드 변경은 아니다. **별도로 추가된 Well TPQ 전제 주석을 검사한 것은 아니다.** 현재 로컬 NFP 전제·reference가 비어 있는 것은 설계상 누락이며, 149건의 주석 오류로 세지 않았다.

## 3. 전체 의미 관계 분류 결과

다음 수치는 **고정 프롬프트를 사용한 LLM 분류 결과**다. 의학적 정답 검증이나 “확정 오류 문항 수”가 아니다. 특히 `related_not_equivalent`에는 일반 통념을 특정 환자 사례로 바꾼 정상적인 변환도 포함될 수 있다.

### FPQ: 질문과 출처 통념 (`source_myth`)

| 분류 | 개수 | 해석 |
|---|---:|---|
| 같은 목표 주장 (`aligned`) | 87 | 같은 주장을 다룸 |
| 관련 있지만 범위·강도 등이 다름 (`related_not_equivalent`) | 420 | 동일하다고 보기 어려움. 오류 확정 아님 |
| 다른 목표 주장 (`different_claim`) | 74 | 질문의 대상과 출처 통념의 대상이 다른 후보 |
| 명제가 아닌 출처 표시 (`metadata_only`) | 1 | 예: From physicians. |
| 불명확 (`unclear`) | 1 | 추가 검토 필요 |
| 합계 | 583 | |

### 자동 분류 74개를 직접 재검토한 결과

`different_claim` 74개를 그대로 확정 오류로 쓰지 않았다. 질문과 `source_myth` 두 필드를 직접 읽은 결과는 다음과 같다. 분류는 주 에이전트의 의미 관계 판단이며 독립적인 인간 평가가 아니다.

| 직접 검토 분류 | 개수 | 뜻 |
|---|---:|---|
| 판정 대상이 다름 (`target_difference`) | 33 | 예: 조산 vs 임신 중단, 기증자 vs 수혜자, 수술 통증 vs 모든 환자의 통증 |
| 출처 주장이 질문에서 함의되지 않음/범위가 다름 (`not_entailed`) | 26 | 예: 개인의 수술 계획을 모든 환자의 유일 치료로 읽음 |
| 관련성 해석 보류 (`borderline`) | 15 | 암시가 가능하므로 완전히 다른 주장이라고 확정하기 어려움 |

이 74개 재검토는 질문·출처 통념 대조에 한정된다. 아래 reference 전체 분류를 독립 검증한 것은 아니다. 원래 자동 라벨은 보존하고 별도 검토 필드에 기록했다.

### FPQ: 질문과 교정 설명 (`reference_answer`)

| 분류 | 개수 | 해석 |
|---|---:|---|
| 질문의 주장을 설명/교정 (`aligned`) | 289 | 문장의 대상이 맞음. 의학적 정확성 보장은 아님 |
| 질문에 없는 강한 가정을 부여 (`adds_unstated_assumption`) | 292 | 개인 사례→보편 명제, 가능성→필연성 등으로 읽는 후보 |
| 다른 목표 주장 (`different_claim`) | 1 | 별개 내용을 설명하는 후보 |
| 불명확 (`unclear`) | 1 | 추가 검토 필요 |
| 합계 | 583 | |

두 표는 같은 583개를 서로 다른 필드 쌍으로 센 것이다. **숫자를 합산해 오류 문항 수로 쓰면 안 된다.**

### NFP 149개

전제·교정 설명은 모두 현재 원장에서 제공하지 않는다(`absent_by_design`). 따라서 FPQ와 같은 3필드 대조는 불가능하다. 대신 원본 `example_assumption` 메모와 질문을 별도로 대조했다: {'aligned_context': 29, 'adds_unstated_assumption': 118, 'different_claim': 2}. 이 메모는 NFP 정답 교정문이 아니므로 불일치 수를 데이터 정답 오류 수로 해석하지 않는다.

## 5. 현재 실험에 대한 의미

- `fpq_44`처럼 질문·교정 설명은 맞고 출처 통념만 다른 경우가 있다. 이것만으로 질문의 FPQ 라벨이나 모델 답변 전체가 잘못됐다고 할 수 없다.
- 현재 FPQ Well 채점에는 질문, `presuppositions[0]`, `reference_answer`가 함께 들어간다. 출처 통념이 다른 주장을 가리키면 **채점 입력이 혼재하는 경로는 확인된다.** 그러나 실제 점수가 얼마나 바뀌는지는 동일 답변의 통제된 재채점 없이는 알 수 없다.
- 질문만으로 전제를 추출하는 단계의 출력 오류와 이번 참조 필드 정합성 문제는 다르다. 이번 검사만으로 Sol 또는 각 모델의 추출이 틀렸다고 판단하지 않는다.
- NLA/AO 설명을 특정 `source_myth`와 일치하는지로만 평가하면, 질문의 실제 오류를 짚어도 불일치로 판정될 수 있다. 해당 A6000 분석의 46개 명단과 입력을 확보한 뒤 확인해야 하며, 이번 검사로 그 46개나 이전 0건/1건 결론을 바꾸지 않는다.
- 새로운 문항 삭제·라벨 변경·점수 교체는 하지 않았다. 현재 표는 기존 규약 그대로 유지한다. 후속 분석에서는 직접 확인한 사례부터 질문의 실제 목표 주장과 원본 reference를 구분해서 점검할 수 있다.
