# 세 번째 리뷰 — Task·Table 명세와 해석에 대해 (2026-09-09)

13의 Task 1–3·Table 1–3 명세와 문서 세션의 설명에 대한 리뷰. 원문 그대로 보존한다. 반영 내역은 [12 §11](../12_discussion_decisions.md).

---

**큰 구조에는 동의합니다. Task 1은 '어떻게 고를까', Task 2는 '골라서 개입하면 좋아지나', Task 3은 '다른 의료 QA에도 지장이 없나'를 담당하면 됩니다.** 다만 지금 명세에는 가설을 미리 결론으로 취급하는 부분과 필요한 비교가 빠진 부분이 있어서, 아래처럼 고치는 게 좋겠습니다.

**1. Task·Table의 역할은 유지하되, Task 3은 보존 평가로 둡니다.**

| 구분 | 답할 질문 | 논문에 들어갈 결과 |
|---|---|---|
| **Task 1: 교정 대상 판별** | 질문 텍스트·명시적 전제 검토·CoT에 비해 내부 신호가 추가 정보를 주는가? | **Table 1:** 판별 성능과 비용 |
| **Task 2: 선택적 교정** | 정상 질문의 손실을 제한하면서 FPQ 교정을 개선하는가? 그 개선은 게이트와 개입 중 어디서 오는가? | **Table 2:** 주 결과 / **Table 3:** 구성 요소 비교 |
| **Task 3: 의료 QA 보존** | 고정한 시스템을 다른 의료 QA에 적용해도 성능이 유지되는가? | **Table 2의 QA 열:** 보존 평가 |

Task 3은 별개의 새 방법이나 독립적인 novelty가 아닙니다. **Task 2에서 제안한 방법의 적용 범위를 확인하는 평가**입니다. 따라서 task 세 개와 contribution 세 개를 일대일로 맞출 필요도 없습니다.

Table 번호는 현재대로 유지해도 됩니다. 다만 독자가 연구의 목표를 놓치지 않도록 서론에서 Table 2의 주 결과를 먼저 소개하면 됩니다. **실험을 실행하는 순서와 논문에서 결과를 강조하는 순서는 달라도 됩니다.**

**2. 가장 먼저 고칠 문장은 "Task 1의 1등이 Task 2의 개입 조건이 된다"입니다.**

이 문장은 다음처럼 바꾸는 게 맞습니다.

> Task 1에서는 각 판별 신호의 성능을 비교한다. Task 2에서는 텍스트·CoT·내부 게이트를 유지한 채 동일한 개입을 적용하여, 판별 성능 차이가 실제 교정 성능과 정상 질문 보존으로 이어지는지 평가한다. 각 방법의 선택과 조정은 내부 개발 분할에서만 수행한다.

이유는 두 가지입니다.

- **AUROC 1등이 실제 개입에서 가장 좋은 게이트라는 보장은 없습니다.** 놓친 문항이 개입으로 고칠 수 없는 문항인지, 잘못 선택한 정상 문항이 개입에 취약한지에 따라 최종 결과가 달라집니다.
- 내부 게이트만 남기면 **"텍스트나 CoT로 골라도 되는 것 아닌가?"에 답할 수 없습니다.**

그리고 전체 out-of-fold 결과를 보고 우승자를 고른 뒤 같은 결과로 최종 성능을 주장하면 선택 편향이 생깁니다. 층·문턱뿐 아니라 **게이트 종류의 선택도 내부 개발 분할에 한정**해야 합니다.

**3. Table 2에는 CoT prompting을 실제 행으로 넣고, Table 3에는 대조 조건을 남깁니다.**

현재 명세는 앞에서 CoT prompting을 본 표에 넣겠다고 했지만, 실제 표에는 그 행이 없습니다. 사용자께서 계속 제기한 질문이므로 부록으로 밀기보다 본 표에 두는 게 맞습니다.

Table 2의 핵심 행은 이렇게 정리하겠습니다.

| 역할 | 방법 |
|---|---|
| 기준 | Plain |
| 기존 프롬프트 방법 | FP Identification, GEPA |
| 직접적인 CoT 대조군 | **균형 잡힌 전제 검토 CoT prompting** |
| 무조건 개입 | Unconditional C steering |
| 기존 조건부 개입 | CAST |
| 같은 내부 게이트의 다른 개입 | Hidden gate + FP prompt |
| 제안 방법 | **Hidden gate + C steering** |

단순히 우리가 만든 C를 항상 더하는 행은 **"Unconditional C steering"**으로 부르는 게 정확합니다. CAA 원 방법을 그대로 재현하지 않았다면 표에서 CAA와 동일시하면 안 됩니다. Hidden gate + FP prompt도 **Two Axes에서 착안한 의료 태스크 적용**임을 표시해야 합니다.

Table 3은 다음 비교를 담당합니다.

| 게이트 | FP prompt | 고정한 C steering |
|---|---:|---:|
| 항상 개입 | 평가 | 평가 |
| 무작위 | 평가 | 평가 |
| 텍스트 | 평가 | 평가 |
| CoT monitor | 평가 | 평가 |
| 내부 probe | 평가 | 평가 |
| Oracle — 진단용 | 평가 | 평가 |

여기서 **같은 C를 두고 게이트만 바꾸면 선택의 효과**, **같은 문항별 게이트 결정을 두고 개입만 바꾸면 개입 방식의 효과**를 볼 수 있습니다. 무작위 조건은 개입 예산을 맞춥니다.

이 통제 실험과 별도로, Table 2의 각 방법은 동일한 개발 데이터·허용폭 아래에서 조정할 수 있습니다. 그래야 구성 요소 비교와 최종 방법 비교를 모두 할 수 있습니다.

**4. 앞서 지적한 과한 해석은 다음 문장으로 교체하면 됩니다.**

| 현재 설명 | 수정할 설명 |
|---|---|
| 짝 응답을 빼면 질문 내용이 사라지고 교정 행동만 남는다 | **같은 질문을 사용해 질문 차이로 인한 교란을 줄인다. 추출 방향의 교정 효과는 실제 개입으로 검증한다.** |
| 텍스트 상한을 넘으면 전제 진위를 읽는 것이다 | **동일한 입력 범위와 평가 분할에서 텍스트 기준선 대비 추가 판별 정보를 평가한다.** |
| Two Axes 수치를 곱하면 기존 방법의 손해가 드러난다 | **해당 계산을 삭제한다. 우리의 평가 데이터와 루브릭으로 각 방법의 교정·오교정 결과를 직접 측정한다.** |
| 내부 모니터가 필요하다 | **내부 모니터가 텍스트·CoT 대비 성능 또는 비용상의 이점을 주는지 검증한다.** |

특히 Two Axes의 47%·61%는 전체 거짓 전제 문항을 분모로 하는 수치라서, 게이트 탐지율에 곱할 조건부 성공률로 쓸 수 없습니다. 이 부분은 표현을 완화하는 정도가 아니라 계산 자체를 빼야 합니다. [원문 §6](https://arxiv.org/html/2607.08456v1#S6)

**5. 평가 규칙도 표를 채우기 전에 구체화해야 합니다.**

- **정상 성능의 주 제약을 지정:** NFP 점수와 TPQ 오교정률은 별도 지표입니다. 각각의 허용폭과 판정 규칙을 정해야 합니다.
- **보존의 판정:** "차이가 유의하지 않다"가 아니라, 성능 차이의 신뢰구간이 사전에 정한 손실 허용폭 안에 들어오는지 봅니다.
- **QA에 적용할 모델을 지정:** cross-fitting에서는 fold별 시스템이 생깁니다. QA에는 어떤 최종 시스템을 적용할지 미리 정하고, QA test로 다시 조정하지 않아야 합니다.
- **코드 수정 선행:** 분할 누수, TPQ 루브릭, 파싱 실패, 판정 캐시 문제를 먼저 해결해야 현재 명세대로 평가할 수 있습니다.

Figure 1도 수정이 필요합니다. **판별기만 있는 Table 1의 행은 PCR·TPQ 좌표가 없으므로 점으로 찍을 수 없습니다.** 게이트와 개입이 결합된 최종 시스템만 찍고, 허용 경계는 `Plain의 TPQ 보존율 − 허용폭`으로 표시하면 됩니다.

이렇게 고치면 논문의 한 문장 주장은 다음으로 정리됩니다.

> **의료 질문의 교정 필요성을 판별해 선택적으로 개입함으로써, 정상 질문과 일반 의료 QA의 성능 손실을 제한하면서 거짓 전제 교정 성능을 개선한다.**

그 안에서 **내부 신호가 필요한지**, **활성값 개입이 프롬프트 개입보다 유리한지**는 각각 입증해야 할 하위 가설입니다. 두 가지를 처음부터 정답으로 박아두지 않는 것이 지금 설계를 더 탄탄하게 만듭니다.
